# 日報の作業報告

対象日に何をしたかを **git のコミットから**拾い、日報の作業報告欄にそのまま貼れる形にする。

**書くのは概要。** コミット件名を全部並べない。ファイル名・関数名・ブランチ名も出さない。
読む相手は他チームや上長で、リポジトリの中身を知らない。

**このスキルは記録するだけ。** 実装もテストもコミットもしない。ファイルも作らない
（出力はチャットに出すだけ。ユーザが日報システムへ貼る）。

## 手順

### 1. 対象日を決める

引数に日付（`2026-09-14` / `昨日` など）があればそれを使う。無ければ**今日**。
**曜日や日付を推測しない。** 機械的に取る。

```bash
date +%Y-%m-%d
```

### 2. コミットを拾う

**全ブランチ・自分のコミット・マージ除外**が既定。worktree で切ったブランチも
本体から `--all` で見えるので、**未マージの作業も日報に載る**（当日やった事実は変わらない）。

```bash
git log --all --no-merges --author="$(git config user.name)" \
  --since="<対象日> 00:00:00" --until="<対象日> 23:59:59" \
  --date=format:'%H:%M' --pretty=format:'%ad|%s' --reverse
```

- 時刻は **author date**（`%ad`）で見る。commit date だとマージやリベースで後ろへずれ、
  午前の作業が午後に化ける
- `--reverse` で時系列順。あとの区分けと読み順がそのまま揃う
- マージコミットは除外する（中身は元のコミットに入っている。二重に数えない）
- 対象日のコミットが 0 件なら、**作文しない。** 「コミットが無い」と伝えて手を止め、
  何をしていたかをユーザに聞く（調査・会議・レビューはコミットに残らない）

あわせて未コミットの差分を見る。

```bash
git status --porcelain
```

差分があれば **「進行中」として別枠**に 1 行で書く。完了した作業として午前・午後のリストに混ぜない。

### 3. 午前・午後に振る

**コミット時刻で機械的に振る。** 推測で動かさない。

| 時刻 | 区分 |
|---|---|
| `～11:30`（11:30 を含む） | 午前 |
| `11:31～12:29` | 午後（昼休みに入り込んだぶんは午後へ寄せる） |
| `12:30～` | 午後 |

午前に着手して午後にコミットした作業は**午後に出る**。それでよい。
「午前から継続」のような注記は入れない（コミットからは判らないので、書けば推測になる）。

### 4. 概要にまとめる

コミット 1 本 = 1 行にしない。**同じ主題のコミットは 1 行に畳む。**

- `feat:` / `fix:` / `refactor:` などの type 接頭辞は落とす。日本語の文にする
- 1 区分あたり **3〜6 行**が目安。多くなるなら畳みかたが足りない
- 粒度は「画面 / 機能」。ファイル名・関数名・変数名・ブランチ名・コミットハッシュは書かない
- `chore:` / `style:` の細かいものは **まとめて 1 行**（例: 「開発環境の設定を調整」）
- テストとドキュメントは、対応する機能の行に含める。独立した作業のときだけ別行にする
- 事実だけ書く。進捗率・所感・次の予定は入れない（日報の別欄の話）

```text
コミット                                   → 出力
feat: 銘柄マスタに新規追加を足す
test: 銘柄マスタの新規追加のシナリオとテストを足す  → 銘柄マスタの新規追加機能を実装（テスト含む）
refactor: マスタ系 API のパスを /masters/ 配下へ移す
refactor: 顧客マスタを /masters/customers へ移す    → マスタ系画面の API パスを仕様に合わせて整理
```

### 5. 出力する

**ファイルは作らない。** 次の形でチャットに出す。そのまま貼れるように、余計な前置きを付けない。

```text
## <対象日>（<曜日>）の作業報告

### 午前（～11:30）
- <概要>
- <概要>

### 午後（12:30～）
- <概要>
- <概要>

### 進行中
- <未コミットの作業>
```

- 片方の区分にコミットが無ければ、その区分は `- （コミットなし）` と書く。節ごと消さない
  （日報の欄が片方だけ埋まっていると、書き漏らしに見える）
- 未コミットの差分が無ければ `### 進行中` の節ごと省く
- 曜日は `date -d <対象日> +%a` で取る。**推測しない**
- 出力のあとに、**元にしたコミット件数**を 1 行添える（例: `元データ: 全ブランチの 12 コミット`）。
  ユーザが拾い漏れに気づける
