# API 仕様

> **仕様そのものの正はバックエンド側リポジトリにある。**
> このディレクトリに置くのは、バックエンド担当から**受領した時点のコピー**。
> ここでコピーを直しても仕様は変わらない。食い違いを見つけたらバックエンド担当に確認し、
> **バックエンド側の原本を直してもらってから受領し直す**。
> そのうえで、**フロントエンド実装の判断基準はこのディレクトリの `openapi.yaml`** とする
> （「仕様の正 = バックエンド側リポジトリ」「フロント実装の正 = `openapi.yaml`」の 2 層で運用する）。

## 置き方

| ファイル | 内容 |
|---|---|
| （このディレクトリ直下） | バックエンドから受領した仕様書の**コピー**をそのまま置く（Excel / Markdown / PDF 等）。編集しない |
| `openapi.yaml` | 受領コピーを AI で変換した OpenAPI 3.1 仕様。**フロント実装上の正とする** |
| `openapi.html` | `openapi.yaml` から Redocly で生成した閲覧用 HTML。**生成物なのでコミットしない**（再生成方法は CONVERSION.md） |
| `redocly.yaml` | Redocly CLI（lint / HTML 生成）の設定 |

## 手順

詳細は [CONVERSION.md](CONVERSION.md)（`/api-to-openapi` スキルの使い方・チェックリスト・反映手順）を参照。

1. バックエンド担当から仕様書を受領し、このディレクトリにコピーを無加工で置く
2. Claude Code で `/api-to-openapi docs/api/<原本>` を実行し、`openapi.yaml` を生成する
3. 報告されたチェックリスト結果を原本と突き合わせて再確認する
4. `openapi.yaml` の `example` を [src/mocks/fixtures/](../../src/mocks/fixtures/) に反映する
5. 未実装の API は MSW ハンドラを追加してフロント開発を進める

仕様の解釈で迷ったら `openapi.yaml` を見る。受領コピーと食い違っていたらバックエンド担当に確認し、
**バックエンド側リポジトリの原本を直してもらったうえで、受領コピーと `openapi.yaml` を作り直す**。
