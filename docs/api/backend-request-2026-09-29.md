## A. 退行・不整合の修正

### #23 操作ログの `操作区分` が一覧と絞り込みで食い違う

**現象（2026-09-29 実測）**

1. `GET /operations/activity-logs` の一覧に、障害管理の `SUSPEND` / `RESUME` とお知らせ管理の `SHOW` / `HIDE` が
   `操作区分` として返る
2. 同じ API に `?operation=SUSPEND` を送ると 400（`指定可能: CREATE, UPDATE, DELETE, BATCH`）になる
3. `openapi.json` の `ActivityLogItem.操作区分` の description にも `CREATE` / `UPDATE` / `DELETE` / `BATCH` の 4 種しか無い

このため、**発注停止とお知らせの操作ログを操作区分で絞り込めません。**
画面は仕様どおり 4 種の区分だけを知っているので、一覧では `SUSPEND` などが英語のまま表示されます。

**お願い**

次のどちらの方針かを回答ください。

- (a) 区分を増やす: `SUSPEND` / `RESUME` / `SHOW` / `HIDE` を `operation` で指定できるようにし、
  `ActivityLogItem.操作区分` の description（できれば enum）と `operation` の指定可能値に反映する
- (b) 4 種に寄せる: 一覧が返す値を `CREATE` / `UPDATE` / `DELETE` / `BATCH` のどれかに寄せる
  （例: 停止・再開・表示・非表示は `UPDATE`）

(a) の場合、フロントは画面の区分の選択肢と表示名（停止 / 再開 / 表示 / 非表示）を足します。
(b) の場合、フロントの変更はありません。

**あわせて確認（優先度低）**

`GET /operations/activity-logs/targets` の対象種別コードは `schedule_times` だけがアンダースコアで、
他はハイフン区切り（`order-suspensions` など）です。動作には影響しませんが、揃える予定があれば
いまのうちに知りたいです（フロントはコードを文字列のまま送り返すだけなので、変わっても追随は軽微です）。
