## 2. 優先度「中」

### #36 `GET /holdings`（`HoldingItem`）の項目の意味と不足（確認・追加）

顧客詳細の外株預り・顧客カード（米国株評価額 / 評価損益）と、預り検索の画面で使っています。

**確認したいこと（description の読みかた）**

| # | 項目 | 気になっている点 |
|---|---|---|
| ① | `評価損益率` | 説明が「(取得金額 / 評価額_JPY) − 1」で、損益と符号が逆になります（評価益の明細で率が負になる）。「(評価額_JPY / 取得金額) − 1」の書き誤りでしょうか |
| ② | `取得金額` | 説明が「平均取得単価 × 前日終値」です。「平均取得単価 × 数量」の誤りでしょうか。単位は円でよいですか（`評価損益 = 評価額_JPY − 取得金額` から円と読んでいます） |
| ④ | `評価損益率` の書式 | 文字列で返りますが、`'12.34%'` と `'12.34'` のどちらか、正の値に `+` を付けるか |

**追加してほしい項目**

| # | 項目 | 用途 |
|---|---|---|
| ③ | `前日終値` と、評価に使った `為替レート` | 画面モックの「参考単価（前日終値）」「参考為替」の列 |
| ⑤ | 売却可能数量（注文中の売りを控除した数） | 預りの「売り」ボタンから新規注文へ数量を引き継ぐ。`GET /balances/{account_no}` の `売却可能株数` と同じもの |
| ⑥ | 行を指す ID | いまは 口座番号・銘柄コード・預り売買区分 の 3 つで 1 行と見ています。この 3 つで一意なら、その旨の回答だけでも構いません |
| ⑦ | 顧客の ID（`m_口座情報.ID`。`GET /masters/customers/{account_id}` のパスキー） | 預り検索の顧客名から顧客詳細（`/customers/<ID>/summary`）へ移るため |

**フロントの暫定**（`src/api/holdings.js` / `src/stores/holdingSearch.js`）:

- ③ は `評価額_USD ÷ 数量`・`評価額_JPY ÷ 評価額_USD` で逆算して出しています
- ① はサーバの値をそのまま出しています
- ④ は `%`・桁区切り・先頭の `+` のどれが付いていても数値として読みます
- ⑤ が無いので、預りの「売り」は数量を引き継がずに新規注文を開きます
- ⑦ が無いので、顧客名を押すたびに `GET /masters/customers` を部店コード・口座番号で引いて ID を得てから移ります（1 往復増えます）

## 3. 優先度「低」

### #37 取消済みの銘柄コードを再登録したときの挙動（確認・仕様の明記）

2026-10-02 に銘柄マスタの実 API E2E を検証したときの実測です。

- 取消済み（`取消区分=1`）の銘柄コードで `POST /masters/symbols/validate` は `valid: true`
- 続く `POST /masters/symbols` は 201 を返し、**新しい行ではなく元の行（同じ ID・元の `作成日時`）が `取消区分=0` で再有効化**された
- そのとき本文に含めなかった `市場名` / `前日出来高` は **null に戻った**（再有効化が全項目の上書きになる）

`openapi.json` には「新規登録時の銘柄コード重複チェック」としか書かれていません。

1. 取消済みの再有効化は意図どおりでしょうか（重複として弾くべきではないか）
2. 意図どおりなら、未送信の項目を null で上書きするのも意図どおりでしょうか
3. どちらの場合も、挙動を description に明記していただけますか

フロントは手を入れていません（実 API E2E `SMR-07` は有効な銘柄コードの重複だけを確かめています）。
