### #44 CA マスタの CA種別・日付の項目・編集での銘柄コード変更（確認・要件）

CA マスタは画面モックと API 仕様（`CAItem` / `CARequest` / `CAUpdateRequest`）で次の 3 点が食い違っています。
フロントは API 仕様に合わせて実装していますが、それでよいかを確認させてください。

**① CA種別の選択肢**

| | 選択肢 |
|---|---|
| 画面モック | 配当 / 株式分割 / 株式併合 / 合併 の **4 種**（名称を値にしている） |
| API 仕様 | `CATypeEnum` の **12 種**（110 現金配当 / 112 株式配当 / 120 株式分割 / 121 無償増資 / 122 有償増資 / 123 子会社割当 / 125 ワラント割当 / 130 会社清算交付金 / 131 合併交付金 / 140 株式併合 / 142 合併交付株 / 220 通常償還） |

1. 検索条件・新規追加・編集とも 12 種をそのまま出してよいでしょうか（モックの 4 種は仮置きという理解でよいか）
2. モックの「配当」「合併」のように**複数のコードをまとめて検索したい**要件はありますか
   （例: 「配当」で 110 と 112 を両方出す）。あるなら `ca_type` を複数指定できるようにしていただく必要があります

**② 日付の項目**

| | 日付の項目 |
|---|---|
| 画面モック | 権利確定日（Ex-Date）/ 権利付最終日（Record）/ 支払日（Pay Date） |
| API 仕様 | 権利付最終日 / 効力発生日 / 支払日（いずれも `YYYYMMDD` の integer） |

3. モックの「権利確定日」は API に無く、API の「効力発生日」はモックに無いですが、**API の 3 つで正**としてよいでしょうか
4. モックの英語表記は「権利確定日 = Ex-Date」「権利付最終日 = Record」となっており、米国株の一般的な用語
   （Ex-Date = 権利落ち日、Record Date = 権利確定日）と対応が合いません。API の `権利付最終日` は
   **Ex-Date の前営業日（最終の権利付き取引日）**という理解でよいでしょうか。また `効力発生日` は何の日付にあたりますか
   （フロントは一覧を効力発生日の降順で出しています）

**③ 編集で銘柄コードを変更できること**

`CA` の PUT はパスキーが `ID` で、`CAUpdateRequest` に `銘柄コード` が入っているため、**編集で銘柄コードを変更できます**。
画面モックの編集ダイアログも銘柄コードが入力可能です。
一方、顧客・銘柄など業務キーでパスを組むマスタは業務キーを編集で変更できない形になっています。

5. CA は編集で銘柄コードを変更できる仕様でよいでしょうか（誤登録した銘柄を直す用途を想定）
6. 自動取込みで入った行（`ユーザー操作フラグ` = 0）の銘柄コードを画面で変えた場合、次回の自動取込みで
   元の銘柄の CA が**別の行として再登録される**ことはありませんか。変更を許さないなら `CAUpdateRequest` から
   `銘柄コード` を外していただけますか

**フロントの暫定**（`src/views/CorporateActionListView.vue` / `src/components/ca/CorporateActionFormFields.vue` / `src/utils/caTypes.js`）:

- CA種別は 12 種をコード順で出し、検索は 1 種ずつです
- 日付は 権利付最終日 / 効力発生日 / 支払日 の 3 列で、モックの「権利確定日」は出していません
- 編集ダイアログの銘柄コードは入力可能です。変更不可になったら読み取り専用にするだけで対応できます
