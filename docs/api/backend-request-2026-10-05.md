## 2. 優先度「中」

### #38 個人／法人で切り替わる選択肢の `GET /codes` への定義（確認・追加）

顧客マスタの新規追加・編集ダイアログで使っています。

**背景**

画面モックの顧客マスタには、「個人／法人」を切り替えると他の選択項目（投資方針・コンプラランク・口座区分など）の
選択肢が入れ替わる仕様があります。この切り替えは `GET /codes` に **法人区分ごとの 2 段**で定義される予定と
聞いていましたが、2026-10-05 時点の実 API で 2 段になっているのは `投資方針` だけで、他のカテゴリは
個人・法人共通の 1 段のままです。

```json
{
  "投資方針": {
    "0": { "1": "利回り・安定重視", "2": "利回り・値上り益重視", "...": "..." },
    "1": { "1": "政策投資", "2": "資金運用", "...": "..." }
  },
  "コンプラランク": { "A": "A", "B": "B", "...": "..." }
}
```

**確認・実装してほしいこと**

| # | 内容 |
|---|---|
| ① | 法人区分で選択肢が切り替わるカテゴリの**一覧**（投資方針のほかに何があるか） |
| ② | ①の各カテゴリの**個人用・法人用の選択肢**（コードと名称） |
| ③ | 形は `投資方針` と同じ `{カテゴリ: {法人区分: {コード: 名称}}}` の 2 段でよいか。別の形にするなら事前に知らせてほしい |

**フロントの暫定**（`src/utils/customerFields.js` / `src/components/customers/CustomerFormFields.vue`）:

- `投資方針` だけ法人区分で選択肢を切り替えています。他の項目は個人・法人で同じ選択肢を出しています
- 2 段のカテゴリを受ける処理（`src/api/codes.js`）は `投資方針` 用に実装済みなので、③ の形なら API 層の変更は要りません。
  2 段になったカテゴリは項目定義に `codesContext: 'corporateType'` を 1 行足すだけで切り替わります
- MSW の `/codes`（`src/mocks/fixtures/codes.js`）には、回答が来るまで提案を入れていません
  （どの項目が対象かフロントだけでは決められないため）

### #39 権限マスタの画面に「預託先参照権限」を出す必要があるか（確認・要件）

[2026-09-30 版](backend-request-2026-09-30.md)の #26 ③（預託先の参照権限を `PermissionFlags` に足すか、ロールで固定するか）の続きです。

**現状**

- 2026-10-05 時点の仕様では、`RolePermissionItem` / `RolePermissionUpdateRequest` に `預託先参照権限`
  （integer・既定 0・「未指定時は現在値を維持（Phase 62）」）が入り、`GET /auth/me` の `PermissionFlags` にも
  `depositary` が入っています
- 一方、画面モックの権限マスタにはこの権限の**列も編集項目も無く**（発注 / マスタ更新 / 運用管理 / 全店参照 の 4 つ）、
  約定照会の預託先は**ロール（manager / supervisor）で固定**の出し分けになっています

**確認したいこと**

| # | 内容 |
|---|---|
| ① | 権限マスタの画面で **5 つめの権限として一覧に出し、編集ダイアログで ON / OFF できるようにする**のか、それとも**ロール固定でバックエンドが値を持つだけ**（画面は触らない）なのか |
| ② | 画面で編集しないなら、約定照会・みずほ注文締の預託先の出し分けを **`/auth/me` の `depositary` に切り替えてよいか**（いまはロールコードで判定しています） |
| ③ | 画面で編集するなら、ロール名の下に出す**説明文の文言**（他の 4 権限は「発注・取消・訂正・Dream状況変更を実行」のような固定文を画面側に持っています） |

  画面から保存しても現在値が維持されます（仕様の「未指定時は現在値を維持」に依っています）
- 約定照会はロールコードで出し分けています
- ① が「画面で編集する」なら、権限の定義に 1 件足し、api 層とフィクスチャに項目を足すだけで対応できます

### #44 CA マスタの CA種別・日付の項目・編集での銘柄コード変更（確認・要件）

CA マスタは画面モックと API 仕様（`CAItem` / `CARequest` / `CAUpdateRequest`）で次の 3 点が食い違っています。
フロントは API 仕様に合わせて実装していますが、それでよいかを確認させてください。

**① CA種別の選択肢**

| | 選択肢 |
|---|---|
| 画面モック | 配当 / 株式分割 / 株式併合 / 合併 の **4 種**（名称を値にしている） |
| API 仕様 | `CATypeEnum` の **12 種**（110 現金配当 / 112 株式配当 / 120 株式分割 / 121 無償増資 / 122 有償増資 / 123 子会社割当 / 125 ワラント割当 / 130 会社清算交付金 / 131 合併交付金 / 140 株式併合 / 142 合併交付株 / 220 通常償還） |

1. 検索条件・新規追加・編集とも 12 種をそのまま出してよいでしょうか（モックの 4 種は仮置きという理解でよいか）
2. モックの「配当」「合併」のように**複数のコードをまとめて検索したい**要件はありますか
   （例: 「配当」で 110 と 112 を両方出す）。あるなら `ca_type` を複数指定できるようにしていただく必要があります

**② 日付の項目**

| | 日付の項目 |
|---|---|
| 画面モック | 権利確定日（Ex-Date）/ 権利付最終日（Record）/ 支払日（Pay Date） |
| API 仕様 | 権利付最終日 / 効力発生日 / 支払日（いずれも `YYYYMMDD` の integer） |

3. モックの「権利確定日」は API に無く、API の「効力発生日」はモックに無いですが、**API の 3 つで正**としてよいでしょうか
4. モックの英語表記は「権利確定日 = Ex-Date」「権利付最終日 = Record」となっており、米国株の一般的な用語
   （Ex-Date = 権利落ち日、Record Date = 権利確定日）と対応が合いません。API の `権利付最終日` は
   **Ex-Date の前営業日（最終の権利付き取引日）**という理解でよいでしょうか。また `効力発生日` は何の日付にあたりますか
   （フロントは一覧を効力発生日の降順で出しています）

**③ 編集で銘柄コードを変更できること**

`CA` の PUT はパスキーが `ID` で、`CAUpdateRequest` に `銘柄コード` が入っているため、**編集で銘柄コードを変更できます**。
画面モックの編集ダイアログも銘柄コードが入力可能です。
一方、顧客・銘柄など業務キーでパスを組むマスタは業務キーを編集で変更できない形になっています。

5. CA は編集で銘柄コードを変更できる仕様でよいでしょうか（誤登録した銘柄を直す用途を想定）
6. 自動取込みで入った行（`ユーザー操作フラグ` = 0）の銘柄コードを画面で変えた場合、次回の自動取込みで
   元の銘柄の CA が**別の行として再登録される**ことはありませんか。変更を許さないなら `CAUpdateRequest` から
   `銘柄コード` を外していただけますか

**フロントの暫定**（`src/views/CorporateActionListView.vue` / `src/components/ca/CorporateActionFormFields.vue` / `src/utils/caTypes.js`）:

- CA種別は 12 種をコード順で出し、検索は 1 種ずつです
- 日付は 権利付最終日 / 効力発生日 / 支払日 の 3 列で、モックの「権利確定日」は出していません
- 編集ダイアログの銘柄コードは入力可能です。変更不可になったら読み取り専用にするだけで対応できます
