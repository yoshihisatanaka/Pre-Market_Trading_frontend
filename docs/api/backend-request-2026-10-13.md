### #67 ユーザ管理マスタの画面モックと `/masters/users` の食い違い（追加・確認）

**背景**: 画面モックに 2026-10-12 にユーザ管理マスタが入りました。Entra ID のメールアドレスで利用者を特定し、
ロール 1 つと有効／無効を割り当てる画面です（新規追加・削除は無く、編集はロールと状態だけ）。
#5 で「ユーザは管理画面で管理しない」としていた前提が、モックで変わりました（削除が無いのは同じです）。

`OperatorItem` / `GET /masters/users` / `PUT /masters/users/{operator_code}` と、次の 5 点で食い違います。

**依頼内容**

| # | 内容 |
|---|---|
| ① | **利用者のキー**: モックの 1 列目と検索は Entra ID のメールアドレスですが、`OperatorItem` にメールアドレスがありません（キーは `操作者コード`）。ログインをメールアドレスで引く想定なら、`OperatorItem` にメールアドレス（と、モックが内部に持つ Entra の Object ID）を足してください。あわせて、一覧に出す **`部店名`**（他の `*Item` と同じく `部店コード` と対で）と、氏名の下に添える **氏名カナ**（任意）もお願いします |
| ② | **検索**: モックの「メールアドレス・氏名」のキーワード（部分一致）と、状態の「無効」だけの絞り込みに当たるクエリがありません（`include_inactive` は「無効も含める」だけ）。`keyword`（社員コード・メールアドレス・氏名の部分一致）と、有効／無効を選ぶクエリ（例 `active=true\|false`）を足してください |
| ③ | **更新の保護**: モックは「最後の有効な管理責任者は無効化・ロール変更できない」「自分自身は無効にできない」をサーバ側で拒否します（文言「最後の有効な管理責任者は無効化または権限変更できません。」「自分自身を無効にはできません。」）。`save_operator_account` にこの検査がありません。入れるかどうか、入れるなら 400 の `detail` の文言を教えてください |
| ④ | **権限**: モックは権限マスタに 7 つ目の「ユーザ管理」を足し、それを持つロールだけがこの画面を開け・更新できます。`PermissionFlags` に該当が無く、`PUT` は `master` を要求します。「ユーザ管理」を分けるなら `PermissionFlags` と `RolePermissionItem` に足してください |
| ⑤ | **参考（確認だけ）**: `PUT` は部分更新ではなく、本文に無い `氏名` / `部店コード` / `受注者コード` が null で上書きされます（他マスタの `*UpdateRequest` と違います）。フロントはいまの値を送り返しているので困ってはいませんが、意図どおりかだけ教えてください |

**フロントのいまの扱い**: 1 列目は社員コード（`操作者コード`）、所属部店名は部店の選択肢（`GET /branches`）から引き、カナは出しません。
キーワードは `keyword` で送っています（実 API は無視するので絞り込みが効きません）。状態は「すべて / 有効」の 2 つです。
更新の保護はサーバの 400 をそのまま出すだけで、権限は `master` で代用しています。

## 3. D: 仕様の確認

### #66 操作ログの変更項目が画面の項目名と一致しない（確認 または 追加）

**背景**（2026-10-13 実測。#62 の続き）: 仮計算マスタの画面で 4 項目（取引所税（%）/ スプレッド（円/USD）/ 現地手数料率（%）/
NISA仮計算用為替上乗せ率（%））を変えたところ、`GET /operations/activity-logs` の `変更項目` は次のとおりでした（履歴 ID 6）。

```json
["NISA為替上乗せ率", "更新日時", "更新者", "為替スプレッド", "現地手数料率_bp"]
```

食い違いは 3 点です。

| # | 食い違い |
|---|---|
| (1) | 項目名が DB の列名のまま（`為替スプレッド` ↔ 画面「スプレッド」、`現地手数料率_bp` ↔「現地手数料率」、`NISA為替上乗せ率` ↔「NISA仮計算用為替上乗せ率」、`取引所税率` ↔「取引所税」） |
| (2) | 値の単位が画面と違う（`現地手数料率_bp` は bp で 15.0 → 15.0001、画面は % で 0.150000 → 0.150001。`取引所税率` は比率、画面は %）。名前だけ直しても数値が合いません |
| (3) | `更新日時` / `更新者` が変更項目に入る。仮計算マスタに限らず、顧客（`["更新日時","更新者","顧客名"]`）・銘柄でも同じです |

個別履歴 `GET /masters/calculation-settings/history` の `差分データ` は (3) の 2 項目を含まないので、
操作ログ側だけが変更前後の JSON 全体から差分を取り直していると読んでいます。

**依頼内容**

| # | 内容 |
|---|---|
| ① | `変更項目` / `差分` から監査列（`更新日時` / `更新者` / `作成日時` / `作成者`）を外してください（個別履歴の `差分データ` と同じ扱い。全対象種別に共通） |
| ② | 項目の表示名を返してください（例: `差分` の各要素に `表示名` を足す、または `変更項目` と同じ並びの `変更項目名` を足す）。表示名は値を変換せず、単位を名前に含めて画面に寄せる形を想定しています（例 `現地手数料率（bp）` / `取引所税率（比率）`） |
| ③ | ② を入れない場合は、項目名は DB 列名のままとする方針を回答ください（フロントが対象種別ごとに表示名の辞書を持ちます） |

**補足**: 同じ操作で変えたはずの取引所税が `変更項目` に無く、`差分` でも `取引所税率` は前後とも 0.0000206 でした。
取引所税率だけを変える PUT で載るかをフロントで実測中です。再現したら追って連絡します（本書では依頼しません）。

**フロントのいまの扱い**: 応答の項目名をそのまま出しています。② が入れば表示名を読み、③ なら対象種別ごとの辞書を置きます。
