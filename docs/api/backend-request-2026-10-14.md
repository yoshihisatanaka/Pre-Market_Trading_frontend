## 2. C: 改修のお願い（項目の追加）

### #69 コードマスタ（`app/config/codes.json`）に 3 カテゴリを足してほしい（追加。#30 の続き）

**背景**: 画面の選択肢はすべて `GET /codes` から取る方針です。2026-10-14 にフロントが自前で持っている選択肢を洗い出したところ、
次の 3 つは `/codes` にも enum にも取得先がありませんでした。

| # | 選択肢 | 使う画面 | 取得先が無い理由 |
|---|---|---|---|
| ① | `実行者区分` | 操作ログ（検索） | `GET /operations/activity-logs` の `actor_group` の値と名称が、クエリの description にしか無い |
| ② | `預託先区分` | 銘柄マスタ（検索・追加・編集）/ 約定照会（検索） | `/codes` の `注文ルート` は 0〜4 の 5 値だが、`SymbolItem` / `SymbolRequest` の description は「預託先区分 (0:みずほ, 1:IB)」の 2 値で、画面に出す 2 値の取得先が無い |
| ③ | `有効フラグ` | ユーザ管理マスタ（編集の「状態」） | `OperatorUpsertRequest.有効フラグ` は integer 0〜1 で、表示名が無い。#67② で状態の絞り込みが入れば検索もこれを使う |

**依頼内容**

| # | 内容 |
|---|---|
| ① | 下の「契約提案」の 3 カテゴリを `codes.json` に足してください。コードは各 API がいま受け取っている値のままなので、API 側の変更は要りません |
| ② | 銘柄の `注文ルート` に 2〜4 を入れられるかを教えてください。入れられるなら `預託先区分` は不要で、選択肢は `注文ルート` の 5 値にします |

**契約提案**: 形は既存の `codes.json` と同じ `{カテゴリ: {コード: 名称}}` です。名称はいまの画面の表示に合わせました。

```json
{
  "実行者区分": {
    "sales_ifa": "営業員・IFA",
    "manager": "管理者・管理責任者"
  },
  "預託先区分": {
    "0": "みずほ",
    "1": "IB"
  },
  "有効フラグ": {
    "0": "無効",
    "1": "有効"
  }
}
```

- `実行者区分` の値は、`actor_group` の description（10-06 の回答 #38 ③）のままです
- `預託先区分` は、`注文ルート`（0〜4）のうち銘柄に設定できる 2 値です。名称は `/codes` の `注文ルート` と同じにしました
  （画面モックの銘柄マスタは「IB証券 / みずほ証券」と書きますが、名称は `/codes` に寄せる方針で揃えます）
- `有効フラグ` はユーザ管理マスタの `有効フラグ`（integer）です。`/codes` のキーは文字列なので、送るときはフロントの api 層が integer に直します

**フロントのいまの扱い**: 3 つともフロントの定数で出しています。入ったら `/codes` から取るように替えます。
なお同じ洗い出しで、`/codes` に取得先があるのにフロントが定数で持っていた選択肢（新規注文の売買区分・資金性格など 11 項目）も見つかりました。
これはフロント側で `/codes` に寄せます（依頼はありません。表示名は `/codes` の名称を正とします）。
