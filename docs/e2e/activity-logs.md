# 操作ログ

- 略号: `AL`
- 画面: `src/views/ActivityLogListView.vue`
- テスト: `e2e/activity-logs.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（61 件・特定の対象キー・特定の差分）を
使うので、実 API に当てると通らない。実 API との噛み合わせを見る版は [activity-logs-real-api.md](activity-logs-real-api.md)。

`/operations/activity-logs` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` /
`start_date` / `end_date` / `operator` / `category` / `operation` / `target_types` / `target_key` / `sort`）を
正としているため、**実ブラウザでの URL と画面の同期**（AL-15）と**ブラウザバック**（AL-16）をここで守る。
既定値（並び順の「新しい順」など）は URL に出ない。

検索条件と列の呼び名は画面モックに合わせてある。モックの「操作区分」（マスタ更新 / 運用管理）は実 API に無く、
対象種別から導く区分で、検索では対象種別のカンマ区切り（`target_types`）に展開して送る（AL-18）。
モックの「操作内容」（登録 / 更新 / 削除 …）が実 API の `operation`（AL-03）。
モックにある 業務操作 / 実行者区分 / 結果 は実 API に無いので置かない（`docs/api/requests.md` #38）。

既定モックは 61 件（1 ページ 50 件）で、操作日時の**降順**。先頭 21 件が対象種別 8 種・操作区分 9 種を
一通り含み、残り 40 件は古い日付の顧客マスタの更新。先頭行は銘柄マスタ `AAPL` の更新。
対象機能の選択肢は `GET /operations/activity-logs/targets`（8 種。運用管理は 発注停止 / お知らせ の 2 種）から引く。

この画面は**読むだけ**で、追加・訂正・削除の導線を持たない（AL-12）。
行ごとの操作は「詳細」ダイアログを開くことだけ（AL-13 / AL-14）。

`mockApi()` は固定の body を返すだけで `offset` やクエリを解釈しないため、
ページングと絞り込み（AL-02〜AL-10 / AL-15 / AL-16 / AL-18）はクエリを実際に処理する既定ハンドラで見る。

初期表示のローディングはモック応答が即座に返るため実ブラウザでは安定して観測できない。
ローディング表示の出し分け、`?offset=7` のような端数の `offset`、未知の操作内容・区分・並び順を手で URL に
書いたときの扱い、区分と対象機能の優先、値の整形（`formatActivityAt` / `formatActivityValue`）の境界は
画面の導線からは起こらない（または純関数で閉じる）ので、`docs/unit/` の単体テスト側の担保に譲り、ここには書かない。
