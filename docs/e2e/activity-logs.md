# 操作ログ

- 略号: `AL`
- 画面: `src/views/ActivityLogListView.vue`
- テスト: `e2e/activity-logs.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（56 件・特定の対象キー・特定の差分）を
使うので、実 API に当てると通らない。実 API との噛み合わせを見る版はまだ無い。

`/operations/activity-logs` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` /
`start_date` / `end_date` / `operator` / `operation` / `target_types` / `target_key` / `sort`）を
正としているため、**実ブラウザでの URL と画面の同期**（AL-15）と**ブラウザバック**（AL-16）をここで守る。
既定値（並び順の「新しい順」など）は URL に出ない。

既定モックは 56 件（1 ページ 50 件）で、操作日時の**降順**。先頭 16 件が対象種別 6 種・操作区分 4 種を
一通り含み、残り 40 件は古い日付の顧客マスタの更新。先頭行は銘柄マスタ `AAPL` の更新。
対象種別の選択肢は `GET /operations/activity-logs/targets`（6 種）から引く。

この画面は**読むだけ**で、追加・訂正・削除の導線を持たない（AL-12）。
行ごとの操作は「詳細」ダイアログを開くことだけ（AL-13 / AL-14）。

`mockApi()` は固定の body を返すだけで `offset` やクエリを解釈しないため、
ページングと絞り込み（AL-02〜AL-10 / AL-15 / AL-16）はクエリを実際に処理する既定ハンドラで見る。

初期表示のローディングはモック応答が即座に返るため実ブラウザでは安定して観測できない。
ローディング表示の出し分け、`?offset=7` のような端数の `offset`、未知の操作区分・並び順を手で URL に
書いたときの扱い、値の整形（`formatActivityAt` / `formatActivityValue`）の境界は画面の導線からは
起こらない（または純関数で閉じる）ので、`docs/unit/` の単体テスト側の担保に譲り、ここには書かない。
