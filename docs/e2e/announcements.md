# お知らせ管理

- 略号: `AN`
- 画面: `src/views/AnnouncementsView.vue`
- テスト: `e2e/announcements.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（履歴 56 件・現在の本文）を使うので、
実 API に当てると通らない。

`/operations/announcements` の受け入れ条件。お知らせは全画面共通の 1 行だけで、一覧ではなく
**現在値の編集フォーム + 操作履歴の表**の 2 段構成。本体（`GET /operations/announcements`）と
履歴（`GET /operations/announcements/history`）は別々に失敗しうるので、4 状態も別々に見る。
現在の運用状態は `GET /operations/banner` の 発注停止中 から出し、その取得に失敗しても編集は止めない。

既定モックの現在値は **表示 ON・本文あり**（履歴の最新 1 件と同じ状態）、履歴は 56 件（1 ページ 50 件）で新しい順。
既定モックは保存した内容を保持し（現在値の置き換えと履歴の先頭への 1 行追加）、**保存後に履歴が 1 件増える**ところまで見る
（モックの状態はページを開くたびに初期化される）。
履歴のページ位置は URL クエリに載せない（画面内の従属的な表のため）ので、URL との同期はこの画面の条件に含まない。

ローディングの過渡状態（モック応答が即座に返るため実ブラウザでは安定して観測できない）、送信中にボタンが
「更新中…」になって押せなくなる過渡状態、500 文字超の入力（textarea の maxlength で画面から入力できない）、
残り文字数の表示は単体テスト側の担保に譲り、ここには書かない。
サーバの拒否（400 / 422 / 409）は `mockApi()` で PUT の応答を差し替え、理由がフォーム先頭に出ることだけを見る。
