# 残高マスタ

- 略号: `BA`
- 画面: `src/views/BalanceAdjustmentListView.vue`
- テスト: `e2e/balance-adjustments.spec.js`（未作成）

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（62 件・特定の口座番号と銘柄）を使うので、
実 API に当てると通らない。実 API との噛み合わせは別ファイル（`BAR` を予約）で見る。

`/masters/balance-adjustments` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` /
`branch_code` / `account_no` / `customer_name` / `symbol` / `symbol_name`）を正としているため、
**実ブラウザでの URL と画面の同期**をここで守る。既定モックは A支店（123）の 12 顧客に
保有を割り当てた 62 件（1 ページ 50 件）で、**口座番号 → 銘柄コード の昇順**。
ほかに取消済み（論理削除）の行を 1 件持つが、一覧には出ない。

**「銘柄名」での絞り込みは MSW のハンドラだけが解釈する。** 実 API の
`GET /masters/balance-adjustments` に対応するクエリが無く、MSW を切ると黙って効かなくなる
（理由と経緯は `src/api/balanceAdjustments.js` の冒頭）。ここでの期待値もモック前提で書く。

画面モックからの意図的なずれが 3 つあり、そのぶんはモックと期待結果が一致しない。
ページャーを出すこと（モックは全件スクロール）、「新規保有を追加」をヘッダに置くこと
（モックは一覧カードの見出し横）、検索カードに「クリア」があること。

「数量を加算」（BA-11〜18）と「新規保有を追加」（BA-19〜27）はどちらも
**入力 → 確認 → 確定の 2 段階**で、確認ステップから「戻る」で入力値を保ったまま帰れる。
この 2 段階は画面の中だけの話で、サーバへ行くのは「補正を確定」を押したとき 1 回だけ。
登録・更新の既定モックは状態を保持するため、確定後に一覧の値が変わるところまで実ブラウザで見る
（モックの状態はページを開くたびに初期化される）。
