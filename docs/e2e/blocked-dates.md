# 受注不可日マスタ

- 略号: `BD`
- 画面: `src/views/BlockedDateListView.vue`
- テスト: `e2e/blocked-dates.spec.js`

`/masters/blocked-dates` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` / `date_from` /
`date_to`）を正としているため、**実ブラウザでの URL と画面の同期**をここで守る。
既定モックは 2023〜2029 年の 56 件（1 ページ 50 件）。

この画面は現時点で**一覧と検索だけの読み取り専用**で、
[海外休場日マスタ](market-holidays.md)にある新規追加・行ごとの削除・休場区分は持たない。
そのため BD-08 で「表の列が 3 列だけで行に操作ボタンが無い」ことを明示的に守り、
追加 / 削除が実装されたときにこの行が落ちて気づけるようにしておく。

画面上部の説明バナー（国内拠点の受注停止日を管理する旨）は 4 状態の外にあり、
エラーでも 0 件でも消えない。検索カードも同じ理由で消えない（0 件やエラーのときこそ条件を直したい）。
`?offset=7` のような端数の扱いは単体テスト側の担保に譲り、ここには書かない。

|---|---|---|---|---|
| BD-01 | 既定モック | `/` からサイドメニューの「受注不可日マスタ」を click | URL が `/masters/blocked-dates` になり、ヘッダに見出し「受注不可日マスタ」と「再読み込み」ボタンが表示される。件数「56 件」、表に 50 行あり、1 行目に 2023-01-01 / NYSE/NASDAQ / 元日（市場休場） が表示される | 実装済 |
| BD-02 | 既定モック（56 件） | 一覧を開いて「次のページ」を押す | URL に `offset=50` が付き、表が 6 行になる。1 行目に 2029-05-04 相当の 2 ページ目先頭の日付と理由、ページ送りに「56 件中 51–56 件」が表示される | 実装済 |
| BD-03 | 既定モック | 日付（From）に 2025-01-01、日付（To）に 2025-12-31 を入れて「検索」を押す | URL に `date_from` と `date_to` が付き、件数「8 件」・表 8 行になり、すべての行の日付が 2025 年になる | 実装済 |
| BD-04 | BD-03 で絞り込んだ状態 | 「クリア」を押す | URL から検索条件が消え、件数が「56 件」に戻り、日付の入力欄が空になる | 実装済 |
| BD-05 | API が 500 を返す | 一覧を開く | エラーメッセージ（サーバーでエラーが発生しました。）と「再試行」ボタンが表示され、表は表示されない。検索フォームは表示されたまま | 実装済 |

| BD-07 | 既定モック | `/masters/blocked-dates?offset=50` を直接開く | 2 ページ目の状態で表示される（表 6 行、ページ送りの「2」が現在ページ） | 実装済 |
| BD-08 | 既定モック | 一覧を開く | 表の見出しが左から `日付` / `対象市場` / `理由` の 3 列だけで、行に操作ボタン（編集 / 削除）は無い。ヘッダにも「新規追加」は無い | 実装済 |
| BD-09 | 既定モックと 0 件の両方 | 一覧を開く | 画面上部の説明バナーが、データがあるときも 0 件のときも表示される | 実装済 |
| BD-10 | BD-03 で絞り込んだ状態 | ヘッダの「再読み込み」を押す | URL の検索条件は変わらず、件数「8 件」・表 8 行のまま。入力欄の値も保たれる | 実装済 |
