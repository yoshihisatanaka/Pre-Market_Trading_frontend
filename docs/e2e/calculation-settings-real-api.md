# 仮計算マスタ（実 API 接続）

- 略号: `PCR`
- 画面: `src/views/CalculationSettingsMasterView.vue`
- テスト: `e2e/calculation-settings.real-api.spec.js`

[calculation-settings.md](calculation-settings.md)（`PC`）と対象画面は同じだが、**当てる先が違う**。
`PC` は MSW のモックに当てて画面の挙動を細かく固定する。こちらは**実 API
（`/masters/calculation-settings`）に当てて、フロントとバックエンドの噛み合わせだけ**を見る。

## なぜ分けるか

`PC` はフィクスチャの中身（取引所税・スプレッド・現地手数料率・NISA為替上乗せ率の具体的な値）を
期待値にしている。実 API のローカル DB は別の値を持ち、しかも保存のたびに変わるので全滅する。
加えて `mockApi()`（`window.__mswOverrides`）は MSW を切ると効かないため、取得 500 や 422 の
差し替えも成立しない。`PC` を実データでも通るように書き換えると、代わりに画面の精度を失う。

そこで**期待値の立てかたを変えた別ファイル**にする。ここでは「画面の値は API の値を換算したもの」
「保存しても画面に出ない項目は変わらない」のように、**データの中身に依存しない不変条件**だけを書く。
現在値は実行時に画面と API から読んで比べる。

とくに `PCR-04` は**モックでは確認できない噛み合わせ**にあたる。画面は 4 項目しか出さず、
`src/api/calculationSettings.js` も 4 項目と `更新日時` しか送らない（部分更新に任せている）。
送らなかった `消費税率` / `譲渡益所得税率` / `譲渡益住民税率` / `備考` を実 API が本当に保つかは、
実 API に当てないと分からない（MSW のハンドラはそう作ってあるので必ず通る）。

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。実 API に当てるときだけ、
2 つの前提をそろえて実行する。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test calculation-settings.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。

**2026-10-05 時点のローカル実 API は `GET /masters/calculation-settings` が 500**
（「仮計算マスタが初期化されていません（db/migrate_calculation_setting.py を実行してください）」）を返す。
`docs/api/requests.md` #32 ⑤。バックエンド側で初期化されるまでは `beforeAll` の取得で全件が落ちる。

## 実データを書き換える

**仮計算マスタは DB に 1 行しか無い共有設定**で、海外休場日
（[market-holidays-real-api.md](market-holidays-real-api.md)）のように「まだ使われていない
値を選んで副作用を隔離する」ことができない。唯一の行を直接書き換えるしかない。
手本はスライス基準（[slice-criteria-real-api.md](slice-criteria-real-api.md)）で、同じく**退避と復元**で辻褄を合わせる。

- `beforeAll` で `GET /api/masters/calculation-settings` を取り、画面の 4 項目に加えて
  `消費税率` / `譲渡益所得税率` / `譲渡益住民税率` / `備考` まで**全項目を退避**する
- `afterAll` で退避した値を PUT して**元に戻す**。楽観的ロックがあるので、復元の直前に
  もう一度 GET して最新の `更新日時` を添える
- PCR-02 以降は保存のたびに値が動くが、各シナリオが直前の値を実測してから比べるので、
  途中の値には依存しない

**戻せないものがある。**

| 項目 | 実行後 |
|---|---|
| `更新日時` / `更新者` | サーバが付け直すので実行時刻・実行者になる |
| `ユーザー操作フラグ` | 更新のたびサーバが 1 を立てる。0 に戻す手段が API に無い |
| 仮計算マスタの履歴（`GET /masters/calculation-settings/history` が返すもの） | 保存の回数だけ行が積まれる（1 回の実行で 5〜6 行。PCR-02 / 04 の下ごしらえと保存 / 05 の丸め（必要なときだけ）/ 06 の別経路 / 復元） |
| `備考`（元が NULL だった場合） | PCR-04 が目印を入れ、復元で明示的に `null` を送る。実 API が `null` を「触らない」と扱うなら目印が残る（そのときは標準出力に警告を出す） |

したがって**ローカルの開発 DB 専用**。共有環境・本番では実行しない。

PCR-02〜06 は同じ 1 行を順に書き換えるので**順に実行する**。途中だけを `--grep` で
抜き出すと前提（退避と復元）が崩れる。

## 拒否の文言は固定しない

PCR-06（409）の期待結果に、サーバの文言そのものを書かない。
文言はバックエンド側の資産で、変わってもこのテストが落ちる筋合いは無い。
ここで見るのは「拒否の理由が利用者に表示されること」と「値が上書きされないこと」だけ。

例外は PCR-05 の「変更はありません。」で、これは**拒否ではなく分岐の判別**に使う
（差分なしの経路に入ったことを画面から見分ける手段がこの文言しか無い）。

## シナリオ

換算の規則は画面と同じ: 取引所税 = `取引所税率` × 100 を小数第 6 位まで、スプレッド = `為替スプレッド` を
小数第 4 位まで、現地手数料率 = `現地手数料率_bp` ÷ 100 を小数第 6 位まで、NISA = `NISA為替上乗せ率` を
小数第 4 位まで。単位はそれぞれ `%` / `円/USD` / `%` / `%`。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| PCR-01 | MSW off・api 起動。値は問わない | `/masters/provisional-calculation` を開く | 「データあり」状態になり、現在の設定の 4 値（取引所税 / スプレッド / 現地手数料率 / NISA仮計算用為替上乗せ率）が `GET /api/masters/calculation-settings` の値を上の規則で換算した表記と一致し、単位が付いている。ローディング・エラー・未設定の表示は残らない | 未着手 |
| PCR-02 | PCR-01 と同じ | スプレッドを現在値 +0.0001 にして「保存」を押す | 成功の通知が出て（「変更はありません。」ではない）、現在の設定のスプレッドが新しい値になる。API を直接引いても新しい値になっている。開き直しても新しい値のまま | 未着手 |
| PCR-03 | PCR-01 と同じ | 画面を開く | 設定変更フォームの入力欄 4 つの初期値が、API の値を上の規則で換算した値と一致する | 未着手 |
| PCR-04 | PCR-01 と同じ。画面に出ない 4 項目（`消費税率` / `譲渡益所得税率` / `譲渡益住民税率` / `備考`）を API で既定値と区別できる値にしておく | スプレッドを +0.0001 にして「保存」を押す | 保存は届き（スプレッドが変わる）、保存の前後で画面に出ない 4 項目が変わらない（サーバ既定値や NULL に落ちない） | 未着手 |
| PCR-05 | PCR-01 と同じ。4 項目を画面の精度に丸めた値にしておく | 入力欄を触らずに「保存」を押す | 通知に「変更はありません。」が出る。API の `更新日時` は変わらない（履歴も積まれない） | 未着手 |
| PCR-06 | PCR-01 と同じ。画面を開いたあとに、別経路（API 直接）でスプレッドを更新して `更新日時` を進める | スプレッドを別の値にして「保存」を押す | 保存できない理由が表示され、成功の通知は出ない。現在の設定の表示は開いたときのまま。API 側は別経路で入れた値のまま上書きされない | 未着手 |

**PCR-02 以降は直列に実行する**（同じ 1 行を書き換える）。`--grep` で途中だけ抜き出すと前提が崩れる。
