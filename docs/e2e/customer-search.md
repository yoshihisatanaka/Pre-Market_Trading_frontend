# 顧客検索

- 略号: `CSE`
- 画面: `src/views/CustomerSearchView.vue`
- テスト: `e2e/customer-search.spec.js`
- 画面モック: `../premarket-order-202609/python_app/templates/customer_search.html`

`/customers/search` の受け入れ条件。雛形は [_template-search-list.md](_template-search-list.md)（検索一覧・読むだけ）。
ページ位置と検索条件は URL クエリ（`offset` / `branch_code` / `sales_rep_code` / `account_number` / `name`）を正としているため、
**実ブラウザでの URL と画面の同期**をここで守る。あわせて、一覧の行のクリックから顧客詳細（`/customers/<id>/summary`）へ移る導線を通す。
顧客詳細の中身（顧客カード・タブ）はその画面のシナリオが持ち、ここでは「移った先が顧客詳細で、選んだ顧客が出る」までを見る。

読む API は顧客マスタと同じ `GET /masters/customers`（既定ハンドラ `src/mocks/handlers/customers.js`）。
既定モックは有効な行 56 件（1 ページ 50 件）で、並びは口座番号の昇順。先頭行は口座番号 `1230001` の「山田 太郎」。
モックはこのほかに取消済みの行を 1 件持つが、既定の一覧には出ない。部店・扱者は完全一致、顧客名は顧客名・顧客名カナへの部分一致。

ローディングの過渡状態、手で URL に書いた未知のコード、表示件数の倍数でない `offset`、
数字でない口座番号の扱い（api 層が送らない）は、画面の導線からは起こらない（または実ブラウザでは安定して観測できない）ので
単体テスト側の担保に譲り、ここには書かない。
