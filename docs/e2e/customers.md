# 顧客マスタ

- 略号: `CU`
- 画面: `src/views/CustomerListView.vue`
- テスト: `e2e/customers.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（56 件・特定の口座番号・特定の金額）を
使うので、実 API に当てると通らない。実 API との噛み合わせを見る版はまだ無い。

`/masters/customers` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` /
`branch_code` / `handler_code` / `account_number` / `customer_name` / `restriction` /
`account_type` / `corporate_type`）を正としているため、**実ブラウザでの URL と画面の同期**
（CU-14）と**ブラウザバック**（CU-15）をここで守る。

既定モックは部店 4 × 顧客 14 の 56 件（1 ページ 50 件）で、実 API と同じ**口座番号の昇順**。
モックはこのほかに削除済み（論理削除）の行を 1 件持つが、既定の一覧には出ない。

**新規追加と編集はできるが、削除はできない**（2026-09-28 決定）。ヘッダに「新規追加」、
各行の右端に「編集」だけを置き、削除ボタンは無い（CU-11）。**米国株評価額 / 評価損益の列は
同日の決定で一覧から外した**（CU-11 の列の並びで守る）。

追加・編集のダイアログは 4 グループの入力欄を持つ（項目の定義は `src/utils/customerFields.js`。
項目はこれから増えるので、ここでは項目を 1 つずつは見ず、必須の欠けと業務フローだけを見る）。
エラーの出し先は 3 系統で、E2E では 3 つとも実ブラウザで通す。

| 系統 | 出る場所 | シナリオ |
|---|---|---|
| 入力の不備（必須の未入力） | 項目の直下 | CU-17 |
| サーバの事前検証（`POST /masters/customers/validate`）の不合格・警告 | ダイアログ内の箇条書き | CU-18 / CU-19 |
| 通信・サーバ障害（楽観的ロックの 409 を含む） | ダイアログ内の 1 行 | CU-22 |

既定モックは登録・更新した行をページ内で保持する（`resetMockState()` でフィクスチャに戻る。
ページを開き直すと元に戻り、テスト間には持ち越さない）。登録は**件数が 1 増える**ところまで見る。
取消済み（論理削除）の口座番号への登録は再有効化になるので、事前検証が警告を返し、
1 回目は登録せず押し直すと登録される（CU-19）。事前検証の拒否の文言はモックの資産なので、
ここでは口座番号を含む理由が出ることだけを見る。

数値の範囲・書式（`min` / `max` / 生年月日の桁）、送信中の「追加中…」、編集で絞り込み条件の圏外へ
変えたときのページ戻しは単体側（`CustomerListView` と `customerFields` の spec）に委ねる。

**ユーザー操作フラグが 1 の行には色が付く。** 自動取込のままの行と見分けるための印なので、
「色が付いている行がある」ことではなく「フラグ 1 の行だけ背景色が他と違う」ことを守る（CU-10）。

**扱者コードの絞り込みはサーバ側に無い。** 2026-09-15 の OpenAPI 取り込みでこのマスタ一覧は
`/customers` から `/masters/customers` へ移り、そこに `handler_code` が無い。取引規制・口座区分・
個人法人と同じく **MSW のモックだけがこの条件を解釈する**ので、実 API に当てると扱者では絞られない。
ここは MSW に当てる文書なので、下のシナリオの期待値は変わらない。

検索の 7 項目のうちプルダウン 5 つは起動時に 1 回だけ読む `GET /codes` 由来なので、
**選択肢が埋まっていること自体がコードマスタの読み込みが効いている証拠**になる（CU-05）。
顧客名の検索は顧客名・顧客名カナへの部分一致だが、フィクスチャのカナは半角なので
全角で入れてもカナには当たらない。ここでは漢字での部分一致（CU-03）と
他条件との併用（CU-04）だけを見る。

`mockApi()` は固定の body を返すだけで `offset` やクエリを解釈しないため、
ページングと絞り込み（CU-02 / 03 / 04 / 06 / 07 / 08）はクエリを実際に処理する既定ハンドラで見る。

初期表示のローディングはモック応答が即座に返るため実ブラウザでは安定して観測できない。
ローディング表示の出し分け、`?offset=7` のような端数の `offset`、未知のコードを手で URL に
書いたときの扱いは画面の導線からは起こらないので、`docs/unit/` の
`CustomerListView` 側の担保に譲り、ここには書かない。
