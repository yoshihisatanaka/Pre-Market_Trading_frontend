# 約定照会（実 API 接続）

- 略号: `EXR`
- 画面: `src/views/ExecutionListView.vue`
- テスト: `e2e/executions.real-api.spec.js`

[executions.md](executions.md)（`EX`）と対象画面は同じだが、**当てる先が違う**。
`EX` は MSW のモックに当てて画面の細かい挙動を固定する。こちらは**実 API（`GET /executions` と
`GET /executions/export-csv`）に当てて、フロントとバックエンドの噛み合わせだけ**を見る。

## なぜ分けるか

`EX` はフィクスチャの中身（56 件・先頭行は約定ID `#56`・`AAPL` は 7 件・CSV の見出しの並び）を期待値にしている。
実 API に当てるとデータが違うので全滅し、`mockApi()`（`window.__mswOverrides`）は MSW を切ると効かないため、
エラー応答・0 件・ロールの差し替え（`EX-09` / `EX-16` / `EX-18` / `EX-19`）も成立しない。
そこで**データの中身に依存しない不変条件**だけを書く。絞り込みに使う値は、開いた時点（条件なし）に
**画面自身が受け取った `GET /executions` の応答**の先頭の約定から読む。テストから API を直接引かないのは、
`X-User-Code` が画面（`.env` の `VITE_USER_CODE`）と違うと部店の限定（`branch_code` の説明）で見える約定が変わるため。
エラー応答・ローディング・0 件の網羅は `EX` の担当で、ここでは求めない。

この画面の噛み合わせで壊れやすいのは次の 3 つ。

- **クエリ名と値の変換。** URL の `side=sell` を api 層が `side=1`（openapi.json の `1:売 / 3:買`）に変えて送る。
  FastAPI は知らないクエリや値を黙って無視するので、ずれても MSW 版では気づけない
- **一覧と同じ応答の集計（`summary`）。** 件数カードは別の API を呼ばずに `summary` から出す
- **CSV 出力が一覧と同じ条件で落ちること。** 本文はバックエンドが作る（列の並びは画面側で固定しない）

## 2 本目が書き込みでない理由

合格線のスモークは「一覧 1 本・書き込み 1 本」だが、**この画面は読むだけ**（登録・更新・削除の導線が無い）。
そこで 2 本目は**売買区分での絞り込み**にした（`EXR-02`）。売買区分は全件のどちらかに必ず入っていて、
実 API のコード変換（`sell` → `1`）と `summary` の両方を 1 本で確かめられる。

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。実 API に当てるときだけ、前提をそろえて実行する。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test executions.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。

**実 DB には書き込まない**（GET だけ）。各行は独立していて、`--grep` で 1 本だけ抜き出してよい。
約定が 0 件なら `EXR-01` は空状態を確かめて通り、値を 1 行目から読む行は**スキップ**する。
