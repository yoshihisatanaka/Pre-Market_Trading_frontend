# 約定照会

- 略号: `EX`
- 画面: `src/views/ExecutionListView.vue`
- テスト: `e2e/executions.spec.js`

`/executions` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` / `branch_code` / `symbol` / `side` /
`status` / `start_date` / `end_date` / `route`）を正としているため、**実ブラウザでの URL と画面の同期**をここで守る。

既定モックは約定 56 件（1 ページ 50 件）で、並びは約定日時の降順。先頭行は約定ID `#56`。
内訳は 買 38 件 / 売 18 件、出来状況は 全部出来 44 件 / 一部出来 8 件 / 取消済（出来有）4 件、
銘柄 `AAPL` は 7 件、約定日 2026-09-28 は 8 件（`src/mocks/fixtures/executions.js` の生成規則から導く）。

ヘッダの「CSV出力」は、いま一覧に出ている検索条件の全件を `executions.csv` として保存させる。MSW の CSV は
BOM 付き・改行 CRLF・約定日時の昇順（同時刻は ID の昇順）で、`,` `"` 改行を含む値だけを `"` で囲み、null は空欄にする
（`src/mocks/handlers/executions.js`）。預託先（検索欄「預託先区分」と表の列「預託先」）は `/auth/me` のロールが
管理者（`manager`）か管理責任者（`supervisor`）のときだけ出し、それ以外のロールでは URL の `route` を条件に使わない。
既定モックは管理責任者なので、既定の見た目は預託先ありになる。

CSV は `responseType: 'arraybuffer'` で受けるので、ハンドラが付けた BOM は保存されたファイルに残る
（`blob` で受けていた間は MSW の XHR 横取りで落ちていた）。また `route=0` の一覧は
みずほ注文締のモック（`src/mocks/handlers/mizuhoExecutions.js`）が先に応えて約定照会のフィクスチャと件数が合わないので、
預託先の絞り込みは IB（`route=1`）で確かめる。

ローディングの過渡状態、手で URL に書いた未知のコード、表示件数の倍数でない `offset` は、
画面の導線からは起こらない（または実ブラウザでは安定して観測できない）ので単体テスト側の担保に譲り、ここには書かない。
