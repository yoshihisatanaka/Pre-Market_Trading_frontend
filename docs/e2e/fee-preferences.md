# 手数料優遇マスタ

- 略号: `FP`
- 画面: `src/views/FeePreferenceListView.vue`
- テスト: `e2e/fee-preferences.spec.js`

`/masters/fee-preferences` の受け入れ条件。ページ位置と検索条件は URL クエリ（`offset` / `branch_code` /
`account_no` / `fee_pattern`）を正としているため、**実ブラウザでの URL と画面の同期**をここで守る。

1 口座 1 件で、口座ごとの手数料の優遇（パターン方式またはベイシス方式）と為替スプレッドを持つ。
ベイシスを設定した口座はベイシス方式、それ以外はパターン方式で計算される（適用方式はサーバが付ける）。
画面モックは「設定内容は要件整理中」の表示枠だけなので、列と入力項目は実 API（`FeePreferenceItem` /
`FeePreferenceRequest`）から組んでいる（要件は 2026-10-06 のバックエンド回答で確定。`docs/api/requests.md` #11）。

既定モックは有効な行 52 件（4 部店 × 13 口座。1 ページ 50 件）で、並びは口座番号の昇順。先頭行は
`1230001`（山田 太郎・デフォルトパターン・為替スプレッド 0）。モックはこのほかに取消済み（論理削除）の行を
1 件持つが、既定の一覧には出ない。口座は顧客マスタのモックから借りていて、各部店の 14 件目
（`1230014` / `2340014` / `3450014` / `4560014`。松本 久美子）だけは**優遇の登録が無い**（新規追加に使う）。

手数料パターンの検索は「デフォルト」と A〜Z を選べる。デフォルトは空文字という値なので、URL には
`fee_pattern=default` の目印で載り、実 API へは `fee_pattern=`（空文字）で送られる。

一覧・検索（FP-01〜FP-11）に加えて、ヘッダの「新規追加」からの登録（FP-13〜FP-20）・行ごとの編集（FP-21〜FP-27）・
行ごとの削除（FP-30〜FP-34）をこの画面の受け入れ条件に含む。詳細照会・更新履歴・CSV 入出力は実 API にはあるが画面では扱わない。

登録・編集は「サーバの事前検証 → 登録 / 変更」の 2 段で、エラーの出し先が 4 系統に分かれる
（入力の不備は項目の直下 / 事前検証の不合格は箇条書き / 事前検証の警告は注意の箇条書き / 通信・サーバ障害は専用の表示）。
**警告は登録を止めない。** 新規追加では 1 回目に警告を見せてボタンを「続行」に変え、押し直すと登録する。
編集は警告で止まらず、変更の応答が返した警告を成功の通知に添える。モックの警告は 2 種類で、
手数料パターンマスタに無いパターン（A〜D 以外）と、方式で使われない項目の入力（ベイシスと掛目を両方入れる、など）。

**パスキーは ID なので、口座番号も編集で変更できる**（業務キーのマスタと違い、読み取り専用にしない）。
更新は取得時の更新日時を送り返す楽観的ロック付きで、409 は通信・サーバ障害と同じ枠に出す。
