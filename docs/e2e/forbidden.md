# アクセス権限がありません（権限のない画面の行き先）

- 略号: `FB`
- 画面: `src/views/ForbiddenView.vue`（`/forbidden`）
- テスト: `e2e/forbidden.spec.js`

`meta.permission` を持つ画面を、その権限の無い操作者が開いたときの受け入れ条件。
**マスタメンテ（`/masters/*`）の 9 画面はすべてマスタ更新権限（`/auth/me` の `権限.master`）が要る**
（2026-09-28 決定）。権限が無ければ `/forbidden` へ置き換えで回され、ヘッダの見出しは
「アクセス権限がありません」になる。`/forbidden` はサイドメニューに載らない。

ここで守るのは「URL を直打ちしても弾かれること」「弾かれた先から業務画面へ戻れること」
「操作者が取れないときは権限なしに倒れること」の 3 点。メニューから隠す側は共通レイアウトの
責務なので [layout.md](layout.md) の LAY-16 が持つ。ガードが操作者の読み込み完了を待つこと、
権限の付け忘れ（`/masters/` 配下のルート全部に `meta.permission` があるか）は単体側
（`router/index.spec.js`）に委ねる。

前提の操作者は `mockApi()` で `GET /auth/me` を差し替えて作る。マスタ更新権限の無い操作者は
`src/mocks/fixtures/currentOperator.js` の `salesOperator`。既定モックは管理責任者で、
その場合に `/masters/*` が普通に開くことは各画面のシナリオ（例: CU-01）が守っている。

メニューのマスタメンテには画面が未実装の「為替マスタ」（`/masters/fx`）もあり、ルートが無いので
権限に関わらず「ページが見つかりません」に落ちる（LAY-04）。FB-02 は**ルートのある 8 画面**だけを見る。
為替マスタを実装したら FB-02 の対象に足す。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| FB-01 | `GET /auth/me` がマスタ更新権限の無い営業員 | `/masters/customers` を直接開く | URL が `/forbidden` になり、ヘッダの見出しが「アクセス権限がありません」、本文に権限が無い旨が表示される。顧客の一覧は表示されない | 実装済 |
| FB-02 | FB-01 と同じ | マスタメンテのうち画面が実装済みの 8 つ（顧客 / 権限 / 海外休場日 / 受注不可日 / 銘柄 / CA / スライス基準 / 残高）の URL をそれぞれ直接開く | どれも URL が `/forbidden` になり、見出し「アクセス権限がありません」が表示される | 実装済 |
| FB-03 | FB-01 の状態 | 「注文一覧へ戻る」を押す | URL が `/` になり、ヘッダの見出しが「注文一覧」になる（権限の要らない画面は開ける） | 実装済 |
| FB-04 | `GET /auth/me` が 500 | `/masters/customers` を直接開く | 権限なしとして扱われ、URL が `/forbidden` になり見出し「アクセス権限がありません」が表示される | 実装済 |
