# 為替マスタ（実 API 接続）

- 略号: `FXR`
- 画面: `src/views/FxRateMasterView.vue`（`/masters/fx`）
- テスト: `e2e/fx-rates.real-api.spec.js`

[fx-rates.md](fx-rates.md)（`FX`）と対象画面は同じだが、**当てる先が違う**。
`FX` は MSW のモックに当てて画面の細かい挙動を固定する。こちらは**実 API に当てて、
フロントとバックエンドの噛み合わせだけ**を見る。

この画面は一覧ではなく**現在レート 1 件のカード**なので、一覧の型（件数表示・表・ページ送り）と
`listHelpers` は使わない。見るのは「`/masters/fx/latest` → 詳細 → 事前検証 → 登録 / 変更」の
5 本が実 API で噛み合うことで、とくに**今日（JST）の行の有無で登録（POST）と変更（PUT）に分かれる分岐**と
**楽観的ロックの合札（`更新日時`）の書式**を実物で確かめる。

## なぜ分けるか

`FX` は「現在レート `150.25`・基準日 `2026-07-31`」のようにフィクスチャの中身を期待値にしている。
実 API に当てるとデータが違うので全滅し、`mockApi()`（`window.__mswOverrides`）は MSW を切ると
効かないため、500・404（未登録）・事前検証の不合格の再現も成立しない。それらは `FX` の担当とする。

ここでは**データの中身に依存しない不変条件**だけを書く。現在レート・基準日は実行時に
`GET /masters/fx/latest`（`target_date` = 今日）と `GET /masters/fx/{fx_id}` から読み、画面の表示と比べる。
未登録（latest が 404）のときは空状態に落ちることを、条件付きの期待結果として書く。

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。実 API に当てるときだけ、
2 つの前提をそろえて実行する。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）

あわせて `.env` の `VITE_USER_CODE` が設定されていること（未設定だと更新系が 422 で弾かれる）。

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test fx-rates.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。

## 実データを書き換える

FXR-02 以降は**実 DB の「今日（JST）の USD のレート」を書き換える**。ローカルの開発 DB 前提で、
共有環境・本番では実行しない。

他のマスタのように 2035 年へ逃がすことは**できない**。画面は基準日を選ばせず、
保存先は常に今日（JST）の行だから（2026-09-29 決定。`src/stores/fxRates.js`）。
そこで次の手順で**元のレートに戻す**:

1. **開始時（`beforeAll`）** — `GET /masters/fx?base_date=<今日>&currency_code=USD&include_deleted=true`
   で今日の行の状態を控える。あわせて `latest` の値（画面に出ていた現在レート）も控える
2. **書く値** — 公示（社内）レートは `123.41`〜`123.46` のうち、控えた現在レートと異なるものを順に使う
   （50〜300 円の範囲内なので警告は出ない。途中で落ちたときに人が残骸と見分けるための目印も兼ねる）。
   源泉レートは画面で必須なので、公示レートと組の値（公示 − 0.45 円。`122.96`〜`123.01`）を一緒に書く
3. **終了時（`afterAll`。途中のテストが落ちても走る）** — 控えた状態に応じて戻す

| 開始時の今日の行 | 画面が通る経路 | 終了時に行うこと | 戻した後の DB |
|---|---|---|---|
| 有効な行がある | 変更（PUT） | `PUT /masters/fx/{ID}` で元の `為替レート` と `源泉レート` を書き戻す（合札は送らない） | レートは元どおり。**`更新者` が E2E の利用者、`ユーザー操作フラグ` が 1 になり、変更履歴が 4〜5 件増える** |
| 無い | 登録（POST） | 今日の行を `DELETE /masters/fx/{ID}`（論理削除） | `latest` は前日以前の行に戻る。**今日の基準日の取消済みの行が 1 件残る** |
| 取消済みの行がある | 登録（POST。実 API が復活更新する） | 同上（論理削除し直す） | 同上（取消済みのまま。履歴が増える） |

終了時に `latest` の値（`為替レート` と `源泉レート`）が開始時と一致することを確かめ、一致しなければ失敗させて知らせる。

**戻せないもの:** `ユーザー操作フラグ`（API から 0 に戻す手段が無い）・`更新者`・`更新日時`・
`d_為替履歴` の行。`ユーザー操作フラグ=1` の行をバッチの自動取込みが上書きしない作りなら、
**その日の自動取込みが反映されなくなる**。ローカルの開発 DB でも、レートの自動取込みを
確かめている日には実行しない。

**実行が強制終了されたとき**（コンテナを止めた等で `afterAll` が走らない）は、今日の USD のレートが
`123.41`〜`123.46` のどれか（源泉レートは `122.96`〜`123.01` のどれか）のまま残る。その場合は為替マスタの画面か API で元の値に戻す。

**日付をまたぐ実行は避ける。** JST の 0 時をまたぐと、開始時に控えた「今日」と画面の「今日」がずれ、
戻す対象を取り違える。

FXR-02〜08 は 1 本の流れ（登録または変更 → 再読み込み → 変更 → 警告 → 拒否 → 競合 → 源泉レートの据え置き）なので
**順に実行する**。`--grep` で FXR-03 以降を単独で抜き出すと前提が崩れる
（FXR-01・FXR-02 は単独でも成立する。戻す処理は `beforeAll` / `afterAll` が担う）。

### 期待値に書かないもの

- 現在レートの具体的な値・基準日（実 DB の中身）
- 事前検証の警告・拒否・409 の文言（サーバ側の資産。出し先の枠だけを見る）
- 未登録（404）・500・読み込み中の表示（MSW 版 `FX-02〜04` の担当）
- 入力が空のときの画面側の検査・キャンセル・サイドメニューの遷移（実 API と無関係。`FX-07` / `FX-11` / `FX-12`）
