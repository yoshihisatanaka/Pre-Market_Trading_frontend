# ハードリミットマスタ（実 API 接続）

- 略号: `HR`
- 画面: `src/views/HardLimitMasterView.vue`
- テスト: `e2e/hard-limits.real-api.spec.js`

[hard-limits.md](hard-limits.md)（`HL`）と対象画面は同じだが、**当てる先が違う**。
`HL` は MSW のモックに当てて画面の挙動を細かく固定する。こちらは**実 API
（`/hard-limits`）に当てて、フロントとバックエンドの噛み合わせだけ**を見る。

## なぜ分けるか

`HL` は「5.00%」「10,000 株」「USD 1,000,000」とフィクスチャの中身を期待値にしている。
実 API のローカル DB は別の値を持ち、しかも保存のたびに変わるので全滅する。
加えて `mockApi()`（`window.__mswOverrides`）は MSW を切ると効かないため、
`HL-02`（取得 500）のような応答の差し替えも成立しない。
`HL` を実データでも通るように書き換えると、代わりに画面の精度を失う。

そこで**期待値の立てかたを変えた別ファイル**にする。ここでは
「保存したら数量が 1 増える」「保存しても備考が変わらない」のように、
**データの中身に依存しない不変条件**だけを書く。現在値は実行時に画面と API から読んで比べる。

とくに `HR-04` / `HR-05` は**モックでは絶対に確認できない噛み合わせ**にあたる。
実 API は `備考` と `スライス有効フラグ` を省略した PUT を受け取ると、それぞれ NULL と 1 に
落とす。画面はこの 2 項目を出さないので、`src/api/hardLimits.js` が取得した現在値を
そのまま送り返して保持している。この「送り返し」が実際に効いているかは、実 API に
当てないと分からない。

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。実 API に当てるときだけ、
2 つの前提をそろえて実行する。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test hard-limits.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。

## 実データを書き換える

**この画面が扱うスライス注文設定は DB に 1 行しか無い共有設定**で、海外休場日
（[market-holidays-real-api.md](market-holidays-real-api.md)）のように「まだ使われていない
日付を選んで副作用を隔離する」ことができない。唯一の行を直接書き換えるしかない。

そこで**退避と復元**で辻褄を合わせる。

- `beforeAll` で `GET /api/hard-limits` を取り、3 つの上限に加えて
  `スライス有効フラグ` / `備考` まで**全項目を退避**する
- `afterAll` で退避した値を PUT して**元に戻す**。楽観的ロックがあるので、復元の直前に
  もう一度 GET して最新の `更新日時` を添える
- HR-03 以降は保存のたびに数量が動くが、各シナリオが直前の値を実測してから比べるので、
  途中の値には依存しない

**戻せないものがある。**

| 項目 | 実行後 |
|---|---|
| `更新日時` / `更新者` | サーバが付け直すので実行時刻・実行者になる |
| `ユーザー操作フラグ` | 更新のたびサーバが 1 を立てる。0 に戻す手段が API に無い |
| `d_スライス注文設定履歴` | 保存の回数だけ行が積まれる（1 回の実行で 6 行前後） |

したがって**ローカルの開発 DB 専用**。共有環境・本番では実行しない。
履歴が増えすぎたら DB 側で整理してよい。

HR-03〜07 は同じ 1 行を順に書き換えるので**順に実行する**。途中だけを `--grep` で
抜き出すと前提（退避と復元）が崩れる。

## 拒否の文言は固定しない

HR-06（422）と HR-07（409）の期待結果に、サーバの文言そのものを書かない。
文言はバックエンド側の資産で、変わってもこのテストが落ちる筋合いは無い。
ここで見るのは「拒否の理由が利用者に表示されること」と「現在値が変わらないこと」だけ。
文言の固定は単体側（`docs/unit/views-hard-limit-master-view.md` の `HLV-07`）が持つ。

| ID | 前提 | 操作 | 期待結果 | 状態 |

| HR-02 | 実 API に接続 | ハードリミットマスタを開く | 設定変更フォームの入力欄 3 つの初期値が現在値と一致する（市場関与率は % 換算、他はそのまま） | 実装済 |
