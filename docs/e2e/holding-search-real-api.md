# 預り検索（実 API 接続）

- 略号: `HSR`
- 画面: `src/views/HoldingSearchView.vue`
- テスト: `e2e/holding-search.real-api.spec.js`

[holding-search.md](holding-search.md)（`HSE`）と対象画面は同じだが、**当てる先が違う**。
`HSE` は MSW のモックに当てて画面の細かい挙動を固定する。こちらは**実 API（`GET /holdings`）に当てて、
フロントとバックエンドの噛み合わせだけ**を見る。

## なぜ分けるか

`HSE` はフィクスチャの中身（64 件・先頭行の口座番号やティッカー）を期待値にしている。実 API に当てるとデータが違うので全滅し、
`mockApi()`（`window.__mswOverrides`）は MSW を切ると効かないため、エラー応答や 0 件の再現も成立しない。
そこで**データの中身に依存しない不変条件**だけを書く。絞り込みに使う値（口座番号・部店・顧客名・銘柄・預り区分）は
実行時に開いた時点の一覧（条件なし。顧客検索と同じく開くとすぐ引く）の 1 行目から読む。エラー応答・ローディング・0 件の網羅は `HSE` の担当で、ここでは求めない。

この画面の噛み合わせで最も壊れやすいのは**クエリ名**。URL 上の名前（`account_number` / `stock_name`）を api 層が
実 API の名前（`account_no` / `symbol_name`）に変えて送る。FastAPI は知らないクエリを黙って無視するので、
送出名がずれても MSW 版では気づけない。絞り込みの各行は「送ったリクエストのクエリ」と「表示行がすべて条件を満たすこと」の両方を見る。

## 2 本目が書き込みでない理由

合格線のスモークは「一覧 1 本・書き込み 1 本」だが、**この画面は読むだけ**（登録・更新・削除の導線が無い。
「買い」「売り」は新規注文の画面へ移るだけ）。そこで 2 本目は**口座番号での絞り込み**にした（顧客検索の `CSER-02` と同じ考え方）。

## テストデータが薄い

ローカルの開発 DB は保有が少なく、**保有のある口座（1・3100）が顧客マスタに無い**
（[docs/api/requests.md](../api/requests.md) の「テストデータの不足」#32）。そのため:

- 預りが 0 件なら `HSR-01` は空状態を確かめて通り、`HSR-02` 以降は**スキップ**する
- 1 行目の値が空（`—`）で条件に使えない行は、その行だけスキップする
- `HSR-08`（顧客詳細へ移る）は、表示中の明細のうち**顧客マスタにある口座の明細**が無ければスキップする。
  データが入るまでは実質スキップになる見込み

## 直接発注導線（HSR-09〜11）

操作列の「買い」「売り」は、顧客名と同じく `GET /masters/customers` で顧客マスタの ID を引いてから、
顧客詳細の注文入力タブ（`/customers/<id>/order-entry`。顧客カードとタブが上に出る）へ **URL クエリ**で
顧客・銘柄・売買・預り区分を渡す。注文はまだ送らない（`src/utils/orderEntryQuery.js`）。実 API 版で見るのは次の噛み合わせ:

- クエリに載る値が、**実 API の `GET /holdings` のその明細の値**（部店コード・口座番号・ティッカー）になっている
- 預り区分の読み替え（預りの `預り売買区分` → 注文の `deposit`。1 特定 → `0` / 0 非特定 → `1` / 6 成長投資枠 → `6`。
  4 NISA / 8 継続管理勘定は注文側に無いので載らない。「買い」は成長投資枠を引き継がない）
- 新規注文の画面が、その口座番号で `GET /masters/customers`、そのティッカーで `GET /masters/symbols` を引き、
  **実 API の結果**を欄の横に出す。保有のある口座が顧客マスタに無いと「該当なし」（#32）。
  これは不具合ではなく期待どおりで、期待値は実行時に同じ API を引いて決める
- 数量は渡さない（`GET /holdings` に売却可能数量が無い）。注文数量は空のまま
- 売却不可（`売却不可区分`=1）の明細は「売り」が押せない

**注文は送信しない**（`POST /orders/validate` / `POST /orders` は飛ばない）。発注権限の無い利用者（`HSE-19`）は
`/auth/me` の差し替えが要るので `HSE` の担当。実 API 版は、操作列が「閲覧のみ」ならスキップする
（`VITE_USER_CODE` の利用者に発注権限が無い場合）。

## 仮計算導線（HSR-12〜13）

操作列の「仮計算」は、顧客名・「買い」「売り」と同じく顧客マスタの行 ID を得てから、顧客詳細の仮計算タブ
（`/customers/<id>/calculations`）へ **URL クエリ**で銘柄・売買・預り区分を渡す（`src/utils/calculationQuery.js`）。
発注権限によらず出る（「閲覧のみ」の利用者でも押せる）。実 API 版で見るのは次の噛み合わせ:

- 行 ID の得かた（`src/stores/holdingSearch.js` の `openCustomer`）。明細に `口座ID` があればそれを使って通信せず、
  無ければ `GET /masters/customers` を `account_no`（と `branch_code`）で引く。どちらの経路になるかは実行時に
  実 API の明細の `口座ID` で決める（`HSR-08` と同じ）
- クエリに載る値が、**実 API の `GET /holdings` のその明細の値**になっている。`symbol` は `ティッカー`（空なら `銘柄コード`）、
  `side=sell` 固定、`specific_deposit` は明細の `預り売買区分` そのまま（新規注文の `deposit` と違って読み替えない）。
  ただし仮計算で選べる 1 特定 / 0 一般 / 6 成長投資枠 だけが載り、4 NISA / 8 継続管理勘定は載らない。数量は渡さない
- 仮計算フォームの初期値がクエリに一致する（銘柄は大文字、売買は「売り」、預り区分はクエリの値。クエリに無ければ既定の特定 `1`）

**仮計算は実行しない**（`POST /calculations` は飛ばない。実行の噛み合わせは
[customer-detail-real-api.md](customer-detail-real-api.md) の担当）。
モック `18ed9d1` で削除された現地手数料区分は、2026-10-09 に実装からも外した（`customer-calc-local-fee-category` は無い）。
ここでは前提にも期待値にも使わない。

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。実 API に当てるときだけ、前提をそろえて実行する。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test holding-search.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。

**実 DB には書き込まない**（GET だけ）。各行は独立していて、`--grep` で 1 本だけ抜き出してよい。
