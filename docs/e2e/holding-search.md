# 預り検索

- 略号: `HSE`
- 画面: `src/views/HoldingSearchView.vue`
- テスト: `e2e/holding-search.spec.js`
- 画面モック: `../premarket-order-202609/python_app/templates/holdings_search.html`（原本の写しは `docs/mock/customers-holdings/`。取り込みが古く、列と「仮計算」ボタンが無い）

`/customers/holdings` の受け入れ条件。雛形は [_template-search-list.md](_template-search-list.md)（検索一覧・読むだけ）。
ページ位置と検索条件は URL クエリ（`offset` / `branch_code` / `account_number` / `customer_name` / `symbol` / `stock_name` /
`specific_deposit`）を正としているため、**実ブラウザでの URL と画面の同期**をここで守る。
あわせて、行の顧客名から顧客詳細（`/customers/<id>/summary`）へ、買い / 売りから顧客詳細の注文入力タブ（`/customers/<id>/order-entry`）へ移る導線を通す。
移った先の中身（顧客カード・注文の入力欄）はその画面のシナリオが持ち、ここでは「移った先が正しい画面と引き継ぎ」までを見る。

**開いた時点で条件なしの一覧を出す**（顧客検索と同じ。2026-10-02 に検索前の案内と `submitted=1` の印を外した）。
「検索」は入力した条件をそのまま URL に載せるだけで、条件が空なら URL も空のまま。「クリア」は URL を空にして全件に戻る。

読む API は顧客詳細の外株預りと同じ `GET /holdings`（既定ハンドラ `src/mocks/handlers/holdings.js`）。
既定モックは 64 件（1 ページ 50 件）で、並びはフィクスチャの順（口座ごと）。先頭行は口座番号 `1230001` の「山田 太郎」の `AAPL`。
部店 123 の 3 口座（`1230001` / `1230002` / `1230006`）と部店 234 の 1 口座に画面で確かめたい明細（評価益・評価損・損益 0・
成長投資枠・非特定（表示名「一般」）・売却不可・CA 発生中）があり、部店 345 / 456 の 28 口座に 2 銘柄ずつ機械生成の明細がある
（`src/mocks/fixtures/holdings.js` の冒頭）。部店・口座番号・預り区分は完全一致、顧客名は顧客名・顧客名カナへの部分一致、
銘柄コード／ティッカーは完全一致、銘柄名は部分一致。
預り区分のコード `0`（非特定）の表示名は、実 API の `預り売買区分名` に合わせて「一般」（`src/utils/balanceTypes.js`。残高マスタと共用）。

`HoldingItem` に顧客の ID が無いので、顧客名を押すと `GET /masters/customers` を部店コード・口座番号で引いてから移る
（`docs/api/requests.md` #36 ⑦）。この往復の失敗も 1 行見る。

ローディングの過渡状態、手で URL に書いた未知の預り区分、表示件数の倍数でない `offset`、
数字でない口座番号の扱い（api 層が送らない）、顧客を引いて 0 件だったときの文言は、画面の導線からは起こらない
（または実ブラウザでは安定して観測できない）ので単体テスト側の担保に譲り、ここには書かない。
