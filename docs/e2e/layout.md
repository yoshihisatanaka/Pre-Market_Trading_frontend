# 共通レイアウト（サイドメニュー / ヘッダ）

- 略号: `LAY`
- 画面: `src/components/layout/`（`AppLayout` / `AppSidebar` / `AppHeader`）
- テスト: `e2e/layout.spec.js`
- モック原本: `docs/mock/layout/masters-users.html`
- 単体側のシナリオ: [docs/unit/components-layout-app-layout.md](../unit/components-layout-app-layout.md)

全画面に出る共通部分の受け入れ条件。**個々の画面固有の要素（例: 銘柄マスタの「新規追加」ボタン）は
その画面のシナリオ（[symbols.md](symbols.md)）で扱い、ここには書かない。**
2026-10-02 に預り検索が実装され、メニューの遷移先に未実装の画面は無くなった。そこで LAY-03 は
実装済みの項目（「預り検索」）への遷移で見出しと現在ページ表示の切り替えを見て、「ページが見つかりません」は
LAY-04 でメニューに無い URL を開いて見る形に分けた。LAY-03 で見るのは見出し（ルートの `meta.title`）と
サイドメニューだけで、遷移先の画面の中身は見ない（それは [holding-search.md](holding-search.md) が持つ）。

サイドメニューは押し出し式で開閉する（閉じると画面外へ出て本文が全幅になる。幕は出さない）。
初期状態は **保存値 > 画面幅による既定**で決まり、保存値が無いときだけ 1024px 以下を閉とする。
**リサイズには追従しない**ので、幅を変えるテストは `page.goto()` より前に視点サイズを設定する。

起動時のコードマスタ取得（`GET /codes`）が終わるまで、`AppLoadingOverlay` が画面全体を覆う。
ここで見るのは**起動時に実際に覆われるか**だけで、覆いの中身の出し分けは単体側
（[components-layout-app-loading-overlay.md](../unit/components-layout-app-loading-overlay.md) の `ALO`）が持つ。
応答を遅らせたいときは URL に `?mockDelay=<ミリ秒>` を付ける（`src/mocks/handlers/index.js`）。

ヘッダの市場ステータスと取引時間帯は `GET /market-status` の応答が出どころで、**ローカルの時刻から
推定しない**。モックは固定日のフィクスチャの日付部分を「今日（JST）」へずらして返すので、
時間帯の中身（何時から何時か）と現在のセッションは実行時刻によって変わる。ここで見るのは
**枠組みが出ているか**だけにし、具体的な時刻や境界での切り替えは単体側（`MKS` / `UMS` / `AHD`）が持つ。
休場・取得失敗は `mockApi()` で差し替える。

サイドメニューの区分には権限の要るもの（`navigation.js` の `requiredPermission`。「マスタメンテ」= マスタ更新権限、
「運用管理」= 運用管理権限）があり、`GET /auth/me` の権限が無い利用者・取得に失敗したときは区分ごと出さない。
既定モックは管理責任者（全権限あり）なので LAY-01 は全区分が出る。ここで見るのは**区分の有無だけ**で、
URL を直接開いたときの制限は [access-control.md](access-control.md)（`AC`）が持つ。

サイドメニューの区分は見出しのボタンでアコーディオン開閉する（2026-10-02）。既定は 顧客 / 注文・照会 が開、
マスタメンテ / 運用管理 が閉（`navigation.js` の `defaultOpen`）で、**現在のページを含む区分は既定に関わらず開く**。
閉じた区分のリンクは隠れているだけで DOM には残る（件数は `includeHidden` で数える）。
各画面の「サイドメニューから開く」テストは `e2e/helpers/sideMenu.js` の `clickSideMenuLink()` で、
閉じた区分を開いてから項目を押す。

表示はモック 08986d1 に合わせたバッジ 1 個（丸印・ラベル・JST 側・ET 側）。2026-09-25 に
3 セッションのグリッドから移したので、LAY-02 / LAY-13〜15 の期待値もこの形に書き換えた。

画面は遅延 import なので、メニューを押してからチャンクが届くまで遷移が確定しない（URL も見出しも
現在ページも動かない）。その間はヘッダ上端に読み込み中のバー（読み上げ「画面を読み込んでいます」）が出て、
押した項目に回転マークが付き、本文は `aria-busy` になる（`src/composables/useRouteLoading.js`）。
ここで見るのは **押した直後に反応が返るか / 読み終えたら消えるか / 読み込み中に別の項目を押したら
後から押した方が勝つか / マウスを載せると先読みが起きるか** で、router の各フックの解除条件は単体側が持つ。
遅延の作り方は **`page.route()` で画面モジュール（`/src/views/<画面>.vue`）の取得を遅らせる**。
API の遅延 `?mockDelay` とは別物（モジュール取得は MSW の対象外でネットワークに出るので `page.route` が効く。
API の方は MSW が横取りするので `page.route` では捕まえられない）。

サイドメニューの「注文照会」「Dream登録状況」には、エラーの注文の件数を 1 件以上のときだけ赤い数字で添える（2026-10-09）。
出どころは `GET /orders?status=101,103`（注文エラー）と `GET /orders/dream-status?dream_status=ERROR`（登録失敗・取消失敗）の
`total` で、期待値はフィクスチャ（`orderInquiry.js` / `dreamStatus.js`）とハンドラの絞り込みから導く。
`mockApi()` は path で当てるので、`*/api/orders` を差し替えると注文照会の一覧も同じ応答になる。そのため件数の行は
注文照会以外の画面（`/customers/search`）を開いて見る。件数を変える操作（Dream登録状況の STS変更）で取り直すことは
画面側の [dream-status.md](dream-status.md)（DS-23）が持つ。片方だけ失敗したときの出し分け・遷移ごとの取り直しの回数は単体側が持つ。
