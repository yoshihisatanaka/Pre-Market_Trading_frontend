# みずほ注文締

- 略号: `MZ`
- 画面: `src/views/MizuhoOperationsView.vue`
- テスト: `e2e/mizuho-operations.spec.js`
- 公開モック: `https://uspreorder-vmbhej3k.manus.space/executions/mizuho-operations`

みずほ注文の締め（受付中 / 締め済）を切り替え、締めたあとに注文ファイルを作る画面。
下半分は預託先＝みずほの約定一覧（約定照会と同じ `GET /executions` を `route=0` で絞ったもの）。
ページ位置と検索条件は URL クエリ（`offset` / `branch_code` / `symbol` / `side` / `status` / `date_from` / `date_to`）を正とする。

## この画面の前提（読む前に）

**締めカードの操作は確認ダイアログで確定する。** 結果は画面上部の通知（`mizuho-operations-notice`）に出し、
失敗したときはダイアログを開いたまま中に理由を出す。締め・締め解除の応答で締めカードが切り替わる。

**注文ファイルは 1 回の確定で買い → 売りの 2 冊を作る。** 実 API（`GET /mizuho/export-orders`）が 1 回で 1 冊
（`side=buy` / `sell`）しか出さないため。載せた注文は発注済になり、以降は取消・訂正できない。
みずほ注文締めの前は 400 になるので、モックでも**画面で締めてから**作る（`mockApi()` で締め状態の照会だけを
締め済にしても、モックの中の締め状態は受付中のまま）。売りだけ失敗した場合の出し方は単体テスト（`MZV-16`）が見る
（`mockApi()` は買いと売りを分けて応答できない）。

**締め状態と約定一覧は取得が別。** 4 状態はカードごとに出し分ける。片方が落ちても、もう片方は見られるまま。

**モックの締め状態はページを読み込むたびに受付中へ戻る。** 締めたあとの状態は同じテストの中でだけ続く。

**公開モックとの意図的なずれ:**

- 件数カードの色は一覧の売買列と同じ 買=赤 / 売=青。モックはカードだけ 買=青 / 売=赤 で意味が逆になっていた
- 「一部出来」の件数カードは約定の行数ではなく**一部出来の注文の件数**（`ExecutionSummary.一部出来件数`。処理状況 010 の注文を数える）。ほかの 3 枚は約定の行数で、単位が違う
- 「約定金額(円)」のセルは `ExecutionItem.約定代金_JPY`（約定代金 × 直近の USD レートの概算。為替未登録なら `—`）を出す
- CSV 出力のボタンは「約定一覧」カードの見出し（件数の右）にだけ置く。モックは画面ヘッダにも同じボタンを持つが、同じ操作が 2 つ並ぶため 1 つに寄せた
- 検索カードに「クリア」がある（マスタ系の検索カードと同じ部品）
- 注文ファイル作成にも確認を挟む（作成した注文は発注済になり、以降は取消・訂正できないため）
- 注文ファイルは買い・売りの 2 ファイルになる（モックは 1 ファイル）。実 API が 1 回で 1 冊しか出さないため

## 既定モックの中身

- 締め状態: 受付中。状態変更の記録なし（`history` が空。`src/mocks/fixtures/closing.js`）。
  締め済は `closedMizuhoClosingStatus` で、状態変更履歴（`history`・新しい順）は 3 件:
  2026/09/28 15:10 締め実行 006 → 14:55 締め解除 007 → 14:30 締め実行 006
- 画面は `GET /closing/status?history_limit=3` の `history` を新しい順に全部並べる。締め・締め解除のあとは照会を読み直す
- 締め・締め解除の本文に実行者は載せない。モックは `X-User-Code`（frontend の `VITE_USER_CODE`）を実行者として記録し、
  履歴の先頭に積む（基準日 20260928）。実行者の値は環境で変わるので、E2E は値そのものに依存しない
- 約定: 12 件（`src/mocks/fixtures/mizuhoExecutions.js`）。並びは約定日時の新しい順で、先頭は 約定ID #1（MSFT・証券 太郎）。
  約定代金_JPY は 約定代金 × 150 の四捨五入（null の行は無い）
- 内訳: 買 7 / 売 5、全部出来 8 / 一部出来 2 / 取消済（出来有）2（処理状況 `032` と `034` が 1 件ずつ）。部店 123 が 5 件、約定日 2026-09-26 が 3 件。
  出来状況「取消済（出来有）」（コード `034`）は api 層が `status=032,034` に広げて送る（URL は `status=034` のまま）
- 注文ファイルの元の注文: 買い 3 件（すべて Dream 登録済）/ 売り 3 件（登録済 2・未登録 1）（`src/mocks/fixtures/mizuhoOrders.js`）。
  2 冊作ると 買い 3 件・売り 2 件が載り、今回発注済にした注文は 5 件、Dream 未登録で載せていない注文は売り 1 件
