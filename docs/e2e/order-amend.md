# 注文訂正

- 略号: `OAM`
- 画面: `src/views/OrderAmendView.vue`
- テスト: `e2e/order-amend.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（注文 ID・数量）を使うので、実 API に当てると通らない。

`/orders/:orderId/amend`（見出し「外株注文訂正」）の受け入れ条件。注文照会の「訂正」から入り、
対象注文は画面を開くたびに `GET /orders/{order_id}` で読み直す。発注権限（`権限.order`）が無い利用者は
ルートのガードで「アクセス権限がありません」（`/forbidden`）へ回される。

既定モック（`src/mocks/handlers/orders.js`）の訂正は実 API の説明どおりに状態を持つ。
未発注（000）はその場で書き換え（IN_PLACE）、注文中・一部出来（003 / 010）は原注文を取消依頼（030）にし、
訂正待ち（040）の訂正注文を新しい ID で足す（CANCEL_REPLACE）。**状態はページを読み込むたびに初期化される**ので、
訂正の結果は画面内の遷移（「注文照会へ戻る」）で一覧に戻って確かめる。使う注文は
`#36`（未発注・NVDA 25 株 指値 143.5。`#30` の最新版）、`#34`（注文中・AAPL 500 株 成行）、
`#35`（一部出来・出来 1,200 株）、`#41`（全部出来。訂正できない）。
注文詳細の応答は一覧と同じ派生項目（顧客名・処理状況名・出来数量・有効残数量）を持ち、状況の表示はサーバの 処理状況名 を使う。

レイアウトは画面モック（`order_amend.html`）に合わせてある。訂正対象注文は 4 枠（顧客 / 銘柄 / 売買・預り / 原注文）、
入力は 2 列（注文数量 / 市場区分 / 価格 / 執行条件、訂正理由だけ全幅）。市場区分は 4 ボタンで、アフターを含む 2 つは
「Ph.2予定」で押せない。執行条件（有効期限）は訂正 API が受けないので、いまの値を押せない選択欄で見せるだけ。

ローディングの過渡状態（モック応答が即座に返るため実ブラウザでは安定して観測できない）、送信中のボタンの無効化、
変えた項目だけを本文に載せること（部分更新）、カンマ付きの数量を数値で送ること、成行へ変えたときに単価を送らないこと、
知らない市場区分コードのボタンの追加は、ビューと api 層の単体テスト側の責務とし、ここには書かない。
