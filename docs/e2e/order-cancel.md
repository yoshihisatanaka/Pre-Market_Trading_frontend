# 注文取消

- 略号: `OCN`
- 画面: `src/views/OrderCancelView.vue`
- テスト: `e2e/order-cancel.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（注文 ID・数量）を使うので、実 API に当てると通らない。

`/orders/:orderId/cancel`（見出し「注文取消」）の受け入れ条件。注文照会の「取消」から入り、
この画面そのものが確認の段で、「取消を確定」を押すと取消 API を呼ぶ（確認ダイアログは挟まない）。
対象注文は画面を開くたびに `GET /orders/{order_id}` で読み直す。発注権限（`権限.order`）が無い利用者は
ルートのガードで「アクセス権限がありません」（`/forbidden`）へ回される。取消理由の入力欄は置かない（2026-09-29 決定）。

既定モック（`src/mocks/handlers/orders.js`）の取消は実 API の説明どおりに状態を持つ。
未発注・発注失敗（000 / 101 / 103）はその場で取消済（034）、注文中・一部出来など（003 / 010 / …）は
取消依頼（030。一覧では「取消中」）になる。**状態はページを読み込むたびに初期化される**ので、
取消の結果は画面内の遷移（「注文照会へ戻る」）で一覧に戻って確かめる。使う注文は
`#36`（未発注・25 株。`#30` の最新版）、`#35`（一部出来・3,000 株のうち出来 1,200 株）、`#41`（全部出来。取消できない）、
`#40`（注文エラー。処理状況 101）、`#39`（取消済・60 株のうち出来 20 株）。
注文詳細の応答は一覧と同じ派生項目（顧客名・処理状況名・出来数量・有効残数量）を持つ。状況の表示はサーバの 処理状況名
（フィクスチャの 101 は「発注失敗」で、アプリのコード表の写し「Dream発注失敗」とは違う）。取消対象（未約定残）は
数量 − 出来数量（出来数量はサーバの値）で、有効残数量は使わない（注文エラーは取消できるのに有効残数量が 0 で返る）。

ローディングの過渡状態（モック応答が即座に返るため実ブラウザでは安定して観測できない）、送信中のボタンの無効化、
取消 API の本文、`success: false` の応答の読み替えは、ビューと api 層の単体テスト側の責務とし、ここには書かない。
