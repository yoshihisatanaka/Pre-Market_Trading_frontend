# CSV一括注文

- 略号: `OC`
- 画面: `src/views/OrderCsvUploadView.vue`（`/orders/csv/upload`）/ `src/views/OrderCsvPreviewView.vue`（`/orders/csv/preview`）/ `src/views/OrderCsvCompleteView.vue`（`/orders/csv/complete`）
- テスト: `e2e/order-csv.spec.js`

CSV で注文をまとめて受け付ける 3 画面（取込み → プレビュー → 受付完了）の受け入れ条件。
3 画面は 1 本の業務フローなので 1 ファイル・1 略号にまとめる。

「CSVフォーマット」カードは `GET /orders/csv-spec` の 4 状態（ローディング / エラー / 空 / データあり）を
ここで守る。既定モックは全 22 列（`src/mocks/fixtures/orderCsv.js`。バックエンドの列仕様の写し）で、
必須でないのは 7 列目の「指値単価」だけ（条件「指成区分がLO（指値）の場合は必須」が付く）。

テンプレートDL・事前検証（内容を確認する）・一括受付は処理が入っている。既定モック
（`src/mocks/handlers/orderCsv.js`）の事前検証は**アップロードされた CSV を実際に読む**ので、
E2E はテンプレートの本文（`orderCsvTemplateText` / `orderCsvSampleOrders`。3 行・全行 OK）を元に
CSV を組み、OK / NG / 警告の行を作り分ける。一括受付は送った並びで 90001 からの連番の注文 ID を返し、状態は持たない。

プレビューと受付完了は読み込みを持たない（結果はストアが持つ）。4 状態のうちローディングとエラー（事前検証の失敗）は
取込み画面が受け持ち、プレビューのエラーは一括受付の失敗だけ。URL を直接開いたとき・受付を済ませたあとは空状態になる。

列の値の整形（例の型を文字列に寄せる・condition の null を空にする・区分コードの名前・価格の書式）と、
事前検証の行の変換（日本語キー → アプリ内の注文）は api / utils の単体テストの責務で、E2E に持ち込まない。
事前検証の個々の規則（どの値が NG か）はバックエンドの責務で、E2E は NG と警告が画面に出し分けられることだけを見る。
顧客名は仕様に無い提案の項目（`docs/api/requests.md` #24）で、モックだけが返す。
