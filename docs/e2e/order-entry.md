# 新規注文（外株注文入力）

- 略号: `NO`
- 画面: `src/views/OrderEntryView.vue`（顧客詳細の注文入力タブ `/customers/:customerId/order-entry` と `/orders/new`）
- テスト: `e2e/order-entry.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャの中身（顧客名・銘柄名・前日終値・為替 150.25・採番 1005〜）を
使うので、実 API に当てると通らない。実 API との噛み合わせは [order-entry-real-api.md](order-entry-real-api.md)（`NR`）が見る。

新規注文の画面の受け入れ条件。入力 → 確認 → 完了を 1 つのルートの中で切り替える画面で、URL は段階で変わらない
（URL クエリとの同期はこの画面の条件に含まない。再読み込みで入力へ戻る）。
初期読み込み（受注不可日・海外休場日・発注停止の状態）の 4 状態、送信を受け付けない 2 つの帯（権限なし・全体停止中）、
口座番号・ティッカーの照会、止め方 3 種（画面の入力不備 / サーバの errors / サーバの warnings）、
確認 → 確定 → 完了 → 次の注文、の業務フローを実ブラウザで通す。

既定モックは確定のたびに注文 ID を 1005 から採番する（モックの状態はページを開くたびに初期化される）。
**2 件目の確定で ID が 1 つ進む**ところまで見る。
入口は**顧客 ID 1 の顧客詳細の注文入力タブ `/customers/1/order-entry` をクエリなしで直接開く**（部店・口座番号は空のまま。
フォームはタブの中でも単独でも同じ）。`/orders/new` は口座番号のクエリが無いと顧客検索へ回る（モックと同じ。NO-31）ので、
入口には使わない。顧客詳細・預り検索からの引き継ぎは `customer-detail.md` / `holding-search.md`、
注文照会の「新規注文」（顧客検索へ移る）は `order-inquiry.md` の `OI-15` の担当。

単体テスト側に譲るもの（ここには書かない）:

- ローディングの過渡状態（モック応答が即座に返るため実ブラウザでは安定して観測できない）。
  照会中の「照会中…」、送信中の「確認中…」「確定中…」も同じ
- 入力中の整形の細部（数量のカンマ・全角数字・受注日の `/`・受注時刻の `:`）と、指値の桁数・形式の検査
- 日付計算の境界（期間指定の営業日の数え方、受注日の未来日・7 日超・年またぎ）
- 概算金額の丸め、読み上げの各項目の表示名の対応（区分コード → 表示名）
