# 権限マスタ（実 API 接続）

- 略号: `PMR`
- 画面: `src/views/PermissionListView.vue`
- テスト: `e2e/permissions.real-api.spec.js`

[permissions.md](permissions.md)（`PM`）と対象画面は同じだが、**当てる先が違う**。
`PM` は MSW のモックに当てて画面の細かい挙動を固定する。こちらは**実 API
（`GET /masters/permissions`・`PUT /masters/permissions/{role_code}`）に当てて、
フロントとバックエンドの噛み合わせだけ**を見る。

## なぜ分けるか

`PM` はフィクスチャの中身（「IFA は 4 権限とも不可」「営業員は発注権限だけ許可」）を期待値にしている。
実 API のローカル DB は別の値を持ち、しかも保存のたびに変わるので全滅する。
加えて `mockApi()`（`window.__mswOverrides`）は MSW を切ると効かないため、
`PM-05`（取得 500）・`PM-06`（0 件）・`PM-07`（閲覧のみの操作者）・`PM-12`（409 の差し替え）は成立しない。
そこで**データの中身に依存しない不変条件**だけを書く。権限の値は実行時に API から読み、画面と比べる。

モックでは確かめられない噛み合わせは次の 3 つ。

- 日本語キーの 0 / 1（`発注権限` など）が、画面の「許可 / 不可」に正しく写るか（PMR-03・PMR-05）
- 任意項目の `全店参照権限` を画面が送り、サーバがそれを反映するか（未指定なら現在値維持の仕様なので、
  送り忘れても PUT は 200 で通ってしまう。値が変わったかを API で見ないと気づけない。PMR-02）
- 画面が送らない `説明` が、保存で消えないか（PMR-06）

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。前提は MSW off とバックエンドの起動。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）
3. `.env` の `VITE_USER_CODE` が**管理責任者（supervisor）の社員コード**であること。
   `/masters/*` のルートガードはマスタ更新権限を要し、保存（PUT）は管理責任者にしか許されない。
   管理責任者でないと PMR-02・PMR-05〜08 は「編集」ボタンが無く失敗する（失敗の文言でそう示す）

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test permissions.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。

## 実データを書き換える

PMR-02 以降は**実 DB のロール別権限を書き換える**。ローカルの開発 DB 前提。
ロールは 4 つ固定の共有設定で、試験用の行を新しく作って隔離することができない。
スライス基準マスタ（[slice-criteria-real-api.md](slice-criteria-real-api.md)）と同じく**退避と復元**で辻褄を合わせる。

- 書き換える対象は **管理責任者（supervisor）以外の先頭のロール**（実行時に API の並びから選ぶ）。
  管理責任者自身のマスタ更新権限を落とすと、操作者が `/masters/*` に入れなくなり復元もできなくなるため触らない
- `beforeAll` で `GET /api/masters/permissions` を取り、対象ロールの 4 権限と `説明` を退避する
- 書き込みのシナリオは各自で元の値に戻す。`afterAll` でもう一度 API と突き合わせ、ずれていれば**画面から**戻す
  （PUT は管理責任者に限られ、テストが直接持つ `X-User-Code: e2e` では通らない可能性があるため、
  `VITE_USER_CODE` で動く画面を復元の経路にする）

**戻せないものがある。**

| 項目 | 実行後 |
|---|---|
| 対象ロールの `更新日時` / `更新者` | サーバが付け直すので実行時刻・実行者になる |
| 権限マスタの変更履歴（`GET /masters/permissions/history`） | 保存の回数だけ積まれる（1 回の実行で 6 行前後） |

4 権限と `説明` は実行前の値に戻る。履歴が増えすぎたら DB 側で整理してよい。

**PMR-02 以降は直列に実行する**（同じロールを順に書き換え、`afterAll` で戻す）。
`--grep` で途中だけ抜き出しても復元は効くが、`beforeAll` の退避より前に別の実行が残した値があると、それを「元の値」として扱う。

### 拒否の文言・成功の文言は固定しない

成功メッセージ（「〈ロール名〉の権限設定を更新しました。」「変更はありません。」）と 409 の detail は
サーバが返す文言で、バックエンド側の資産。変わってもこのテストが落ちる筋合いは無いので、
**出たか / 出ないか**だけを見る。文言の固定は MSW 版（`PM-10` / `PM-11` / `PM-12`）が持つ。

### 実 API 版で扱わないもの

- 取得 500・0 件・閲覧のみの操作者・`/auth/me` 失敗時の `/forbidden`（`PM-05`〜`PM-08`）。応答の差し替えが要るので MSW 版の担当
- キャンセルで一覧が変わらないこと（`PM-13`）。PUT を送らない画面内の挙動で、実 API との噛み合わせが無い
