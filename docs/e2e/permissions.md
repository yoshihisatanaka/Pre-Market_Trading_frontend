# 権限マスタ

- 略号: `PM`
- 画面: `src/views/PermissionListView.vue`
- テスト: `e2e/permissions.spec.js`

`/masters/permissions` の受け入れ条件。ロール（IFA / 営業員 / 管理者 / 管理責任者）ごとの 8 権限
—— 参照 / 発注 / 発注（強制） / CSV一括発注 / マスタ更新 / 運用・障害管理 / 操作ログ閲覧 / ユーザ管理
（画面モック 2026-10-12 の列）—— を一覧し、管理責任者だけが編集ダイアログから変更できる。
ここで守るのは「4 ロールの権限が許可 / 不可で読めること」「編集できるかが操作者のロールで出し分けられること」
「保存した値が一覧に反映され、失敗が利用者に伝わること」の 3 点。

操作ログ閲覧は保存しない導出値で、マスタ更新か運用・障害管理を許可したロールに「閲覧可」と出る（チェックは無い）。
参照 / 発注（強制） / CSV一括発注 / ユーザ管理 は実 API に保存先が無い**契約提案**
（[requests.md](../api/requests.md) #75 / #76 / #81）。実 API が返さない間は「—」でチェックできない（PM-18）。
発注（強制）と CSV一括発注は発注が前提（モックと同じ規則。PM-17）。

既定モックは `src/mocks/fixtures/permissions.js`（発注 / マスタ更新 / 運用・障害管理は、IFA が全部不可、
営業員は発注だけ許可、管理者・管理責任者は全部許可。提案の 4 権限は、IFA が参照だけ、営業員が参照と CSV一括発注、
管理者がユーザ管理以外、管理責任者が全部許可）。操作者は `GET /auth/me` で決まり、既定モックは管理責任者（`supervisorOperator`）。
閲覧のみは `viewerOperator`（管理者）に差し替えて見る。
**2026-09-28 から `/masters/*` はマスタ更新権限が要る**（ルートのガード。→ [access-control.md](access-control.md) の AC-05〜07）。
`/auth/me` が失敗すると権限なしに倒れるので、権限マスタは開けず `/forbidden` へ回される（PM-08）。
画面そのものが「取得失敗なら閲覧のみ」に倒すことは、ガードを通らない単体側（`PermissionListView` の spec）が持つ。

保存は `PUT /masters/permissions/{role_code}` で、取得時の更新日時を送り返す楽観的ロック付き。
409 はダイアログ内の通信・サーバ障害の枠に detail をそのまま出す。**拒否の文言はサーバ側の資産なので、
ここでは差し替えた detail が出ることだけを見る。** 既定モックは保存した値をページ内で保持する
（ページを開き直すとフィクスチャの内容に戻る。テスト間には持ち越さない）。

ロールは 4 つ固定で検索条件もページングも無いので、**URL クエリと画面の同期は対象外**。
ローディングの過渡状態（モック応答が即座に返るため実ブラウザでは安定して観測できない）、
保存中に「保存中…」となってボタンが押せなくなる過渡状態、`/auth/me` の応答の細かな形の差（ロールコードの欠落など）は
単体テスト側（画面 `PermissionListView` とストア `permissions` の spec）に委ねる。
