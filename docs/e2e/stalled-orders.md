# 滞留注文抽出

- 略号: `SO`
- 画面: `src/views/StalledOrderListView.vue`
- テスト: `e2e/stalled-orders.spec.js`

`/operations/stalled-orders` の受け入れ条件。ブローカー・自システムの障害で発注できなかった
注文（**注文エラー**）と、別システムで発注しコンファメーションを取り込んだあと未約定のままの
注文（**注文中**）を、1 回の検索で 2 本の一覧に出し分ける画面。

検索条件は URL クエリ（`branch_code` / `account_number` / `symbol`）を正としているため、
**実ブラウザでの URL と画面の同期**をここで守る。ページャは無い（一覧は全件を出す）。

既定モックは注文エラー 3 件 / 注文中 2 件で、内容は公開モックの一覧と 1:1
（`src/mocks/fixtures/stalledOrders.js`）。部店 `123` は注文エラーだけに 2 件あり、
銘柄 `AMZN` は注文中だけに 1 件あるので、**片方だけが空になる**確認に使える。

**CSV 3 種（別システム発注CSVサンプル / 注文エラーのCSV出力 / コンファメーションCSVサンプル）は
サーバを通さずフロントで組み立てる**（`src/utils/stalledOrderCsv.js`）。ここでは実ブラウザで
ダウンロードが起き、ファイル名と中身（BOM 付き・CRLF・ヘッダ・行）が期待どおりかを見る（SO-15〜19）。
値の変換の細かい分岐（クォート・未知の区分の空欄など）は単体テスト側が持つ。

**コンファメーション CSV の取込は API 未実装**で、MSW（`src/mocks/handlers/stalledOrders.js`）が
契約提案（`docs/api/requests.md`）の形で応答する。取込の既定モックは状態を持ち、約定・取消の行は
一覧から外れ、未約定の行は注文中へ移る。**状態はページを開き直すと初期化される**。
ここでは成功 / 行エラー / ファイルごとの拒否（400）/ 通信の失敗（500）の 4 通りを実ブラウザで通す（SO-20〜24）。

アクセス制御（運用管理権限の無い利用者はこの画面に入れない）は画面をまたぐので
[access-control.md](access-control.md)（`AC`）が持つ。
