# ユーザ管理マスタ（実 API 接続）

- 略号: `UMR`
- 画面: `src/views/UserListView.vue`
- テスト: `e2e/users.real-api.spec.js`

[users.md](users.md)（MSW 版）と対象画面は同じだが、**当てる先が違う**。
MSW 版はモックに当てて画面の細かい挙動を固定する。こちらは**実 API に当てて、
フロントとバックエンドの噛み合わせだけ**を見る。

**先頭 2 行（`UMR-01` 一覧 / `UMR-02` 書き込み）はスモークで、10/15 の合格線。**

## なぜ分けるか

MSW 版はフィクスチャの中身（件数・先頭行の社員コードや氏名）を期待値にしている。実 API に当てるとデータが違うので全滅し、
`mockApi()`（`window.__mswOverrides`）は MSW を切ると効かないため、エラー応答・ロールの選択肢の読み込み失敗・0 件の再現も成立しない。
そこで**データの中身に依存しない不変条件**だけを書く。件数・社員コード・ロール・部店は実行時に画面か API の応答から読み取って比べる。
エラー応答・ローディング・0 件・列の並び・バッジの色の網羅は MSW 版の担当で、ここでは求めない。

この画面で特に見たい噛み合わせは次の 5 つ。

- 一覧の配列キーが `operators`（`OperatorListResponse`）で、画面の件数・行が応答の `total` / 配列と噛み合う
- 状態の既定は「すべて」で、画面は `include_inactive=true` を送る。「有効」を選ぶと送らない（仕様の既定 `false` に任せる）
- 更新は `PUT /masters/users/{operator_code}`（パスキーは**業務キーの操作者コード**。行の `ID` ではない）の upsert で、
  本文の `氏名` / `部店コード` / `受注者コード` は**省くと null で上書きされる**。画面は今の値を送り返す（`src/api/users.js` の `updateUser`）
- ロールの選択肢は権限マスタ（`GET /masters/permissions`）、部店の選択肢は `GET /branches` の実 API から来る
- 画面は仕様に無い `keyword` も送る（`docs/api/requests.md` #67）。実 API は黙って無視するので、**件数が変わらないことも、絞られることも期待値にしない**

## 実行方法

既定では**動かない**（`E2E_REAL_API` が無ければ丸ごとスキップ）。実 API に当てるときだけ、
次の前提をそろえて実行する。

1. `.env` の `VITE_ENABLE_MSW` を `false` にして `docker compose up -d --force-recreate frontend`
2. バックエンドを起動しておく（`(cd ../Pre-Market_Trading && docker compose up -d api)`）
3. `.env` の `VITE_USER_CODE` が設定されていること。**マスタ更新権限のある操作者**にする
   （PUT はマスタ更新権限が必要。無いと UMR-02 が通らない）

```powershell
docker compose run --rm -e E2E_REAL_API=1 e2e npx playwright test users.real-api
```

MSW が有効なままだと実 API を見ていないので、各シナリオの冒頭で検出して失敗させる。
バックエンドの `api` と DB は 1 つしかないので、**実 API E2E は worktree 間で排他**にする。

## 実データを書き換える

UMR-02 は**実 DB に PUT を送る**。ローカルの開発 DB を前提にしているので、共有環境では実行しない。

この画面には新規追加・削除が無く、操作者は実運用の利用者そのもの（試験用の行を作れない）。そこで**値を変えない更新**にする。

- 対象は、1 ページ目の応答のうち**ロールコードがロールのプルダウン（権限マスタ）にある最初の行**（無ければスキップ）
- 編集を開いて**ロール・状態を変えずに**「保存」を押す。送る値は取得時の値と同じなので、ロール・有効フラグ・氏名・部店コード・受注者コードは変わらない
- 変わるのは `更新日時` / `更新者`（画面の操作者 = `.env` の `VITE_USER_CODE`）だけ
- 開始前の値を控え、`afterAll` で API を直接引いて比べる。**食い違っていたら控えた値で PUT し直して戻す**（null 上書きの事故を DB に残さない）
- 自分自身を無効にする・管理責任者のロールを外すような変更はしない（値を変えないので起こらない）

**1 回の実行につき DB に残るもの: 対象の 1 行の `更新日時` / `更新者` が変わるだけ。** 行は増えない。
