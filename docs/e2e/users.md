# ユーザ管理マスタ

- 略号: `UM`
- 画面: `src/views/UserListView.vue`
- テスト: `e2e/users.spec.js`

**当てる先は MSW のモック。** 期待値にフィクスチャ（`src/mocks/fixtures/users.js` の 6 件）の中身を
使うので、実 API に当てると通らない。実 API との噛み合わせは [users-real-api.md](users-real-api.md)（`UMR`）が見る。

`/masters/users` の受け入れ条件。雛形 `_template-crud-master.md` から起こしたが、
**新規追加と削除は無い**（画面モック master_users.html に無い。利用者の追加は画面の外で行う）ので、
その行は作らない。一覧・検索（UM-01〜13）と、行ごとの「編集」＝「ユーザの権限設定」（UM-14〜21）を持つ。

ページ位置と検索条件は URL クエリ（`branch_code` / `role` / `status` / `keyword` / `offset`）を
正としているため、**実ブラウザでの URL と画面の同期**（UM-12 / UM-13）をここで守る。

既定モックは 6 件（1 ページ 50 件に収まる）で、並びはフィクスチャの並び（ID 順）。
**状態の既定は「すべて」**で、無効の利用者（社員コード 004）も一覧に出る。「有効」を選んだときだけ
無効の利用者が外れる（仕様の絞り込みが「無効も含めるか」だけなので、「無効」だけを選ぶ選択肢は無い）。
社員コード・氏名のキーワードは実 API に無いクエリで、MSW だけが解釈する（`docs/api/requests.md` #67）。
所属部店名は利用者の行に無く、部店の選択肢（`GET /branches`）から引く。部店の無い利用者は 2 列とも `—`。

編集で変えられるのは**ロールと状態だけ**。社員コード・氏名・所属部店は読み取り専用（UM-14）。
既定モックは更新した行をページ内で保持する（`resetMockState()` でフィクスチャに戻る。テスト間には持ち越さない）。
更新に事前検証も楽観的ロックも無いので、エラーの出し先はモーダル内の 1 行だけ（UM-19）。
MSW の PUT は権限マスタに無いロールコードを 400 で返すが、画面のプルダウンからは権限マスタのロールしか
選べないので、400 は `mockApi()` で再現する。

`mockApi()` は固定の body を返すだけでクエリを解釈しないため、絞り込み（UM-04〜10 / 12 / 13）は
クエリを実際に処理する既定ハンドラで見る。

初期表示のローディングはモック応答が即座に返るため実ブラウザでは安定して観測できない。
ローディング表示の出し分け、ページ送り（既定モックは 1 ページに収まる）、未知の `status` を手で URL に
書いたときの扱い、ロール未選択での保存、氏名の無い利用者の成功メッセージ、絞り込みの圏外へ変えたときの
ページ戻しは画面の導線からは起こらない・起こしにくいので、`docs/unit/` の `UserListView` 側の担保に譲る。
