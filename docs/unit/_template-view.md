# views/〈Name〉ListView（〈画面名〉一覧画面・雛形）

- 略号: `XXV`
- 対象: `src/views/〈Name〉ListView.vue`
- テスト: `src/views/〈Name〉ListView.spec.js`

> **これは雛形。** コピーして `XXV` / `〈…〉` を差し替え、固有の行を足す。`_` 始まりは `check:scenarios` が読まない。
> 原型は `views-symbol-list-view.md`（CRUD）と `views-customer-list-view.md`（検索一覧）。

実際の Pinia ストア + vue-router（`createMemoryHistory`）+ MSW(node) を通して、**4 状態の出し分け**と
「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。`global: { stubs: { teleport: true } }` を付ける。
実ブラウザでの URL 同期は E2E が見る。こちらは E2E では安定して観測できないもの（過渡状態・手で書き換えられた
URL クエリ・応答の差し替え）を担保する。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| XXV-01 | 応答を握ったまま | マウントする | ローディングが表示され、表と空表示とエラーは出ない | 未着手 |
| XXV-02 | `GET /xxx` が 500 | マウントする | エラーの理由と「再試行」が表示され、表は出ない | 未着手 |
| XXV-03 | 0 件の応答 | マウントする | 「該当する〈対象〉はありません。」が表示され、表は出ない | 未着手 |
| XXV-04 | 既定モック | マウントする | 件数と 1 ページぶんの行が表示され、1 行目がフィクスチャ先頭行の値になる（期待値はフィクスチャから導く） | 未着手 |
| XXV-05 | XXV-02 の状態 | 「再試行」を押す（応答は既定に戻す） | 一覧が表示される | 未着手 |
| XXV-06 | `?offset=50` で開く | マウントする | 2 ページ目の行数と「56 件中 51–56 件」が出る | 未着手 |
| XXV-07 | 既定モック | 検索欄に値を入れて「検索」 | ルートのクエリが `〈query〉=値` になり、その条件で再取得される | 未着手 |
