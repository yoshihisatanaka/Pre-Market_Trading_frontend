# composables/useMarketStatus（市場状況の境界タイマー）

- 略号: `UMS`
- 対象: `src/composables/useMarketStatus.js`
- テスト: `src/composables/useMarketStatus.spec.js`
- ストア側のシナリオ: [stores-market-status.md](stores-market-status.md)
- 表示内容の組み立て: [utils-market-status.md](utils-market-status.md)

`AppHeader` のヘッダが「開いてから一度も更新されない」「画面を離れてもタイマーが動き続ける」を
起こさないための土台。この文書のスコープは **境界タイマーと後片付け** だけに絞る。

**`GET /market-status` を叩くのは起動時の 1 回だけ**（`main.js`）。この composable は取りに行かない。
以後はフロント側で時刻を数え、`sessions` の各窓の境界（`JPN開始` / `JPN終了`。tz 付きの絶対時刻）に
達したら表示を切り替える。次の境界までの `setTimeout` を 1 本だけ置き、発火したら次の境界で予約し直す。
最後の境界を過ぎたら、休場の日、未取得のときは予約しない。

例外は受注不可日マスタ / 海外休場日マスタの保存で、そのときはストアが取り直す（`MSS-07`）。
取り直した `status` をこの composable が拾い、境界を予約し直す（`UMS-10` と同じ経路）。

2026-09-25 までは「毎分のティック」と「5 分ごとの再取得」の 2 本だった。再取得をやめたので
`UMS-07`（5 分ごとの再取得）は削除した（**番号は振り直さない**）。

セッションの境界・休場・短縮取引・取得失敗時の見え方は `toMarketDisplay()` の担当
（`MKS-14`〜`MKS-30`）なので、ここでは作り直さない。期待値もラベル文字列を書かず、
`toMarketDisplay()` の戻り値と突き合わせる。

時刻はレギュラーの終了境界（JST 翌 06:00）の 30 秒手前でマウントする。
こうすると「まだ境界に達していない」と「境界で再判定された」を値の差で区別できる。
**通信は起こさない**（store に値を直接置き、`store.load` は差し替えて呼ばれないことを確かめる）。
