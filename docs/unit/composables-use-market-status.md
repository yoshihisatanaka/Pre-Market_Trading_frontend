# composables/useMarketStatus（市場ステータスの定期更新）

- 略号: `UMS`
- 対象: `src/composables/useMarketStatus.js`
- テスト: `src/composables/useMarketStatus.spec.js`

`AppHeader` のバッジが「開いてから一度も更新されない」「画面を離れてもタイマーが動き続ける」を
起こさないための土台。この文書のスコープは **定期更新（60 秒間隔）と後片付け** だけに絞る。

セッションの時刻境界（Pre-Market / Regular / After-Hours / Closed の区切り、夏時間、週末）は
[utils-market-status.md](utils-market-status.md) の `MKS-01`〜`MKS-13` が担保しているので、
ここでは作り直さない。期待値もラベル文字列を書かず、`getMarketStatus()` の戻り値と突き合わせる。

時刻は `MKS-03` / `MKS-04` と同じ境界（`2026-03-02T14:30:00Z` = ニューヨーク月曜 09:30 の
Pre-Market → Regular）を使い、マウント時刻をその 30 秒手前に置く。こうすると
「まだティックが来ていない」と「ティックが来て再判定された」を値の差で区別できる。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| UMS-01 | 現在時刻を `2026-03-02T14:29:30Z`（NY 月曜 09:29:30）に固定 | `useMarketStatus()` を呼ぶホストをマウントする | 戻り値の `.value` が、その時刻の `getMarketStatus()` と同じ `key` / `label`（初回表示に 1 分待たない） | 実装済 |
| UMS-02 | UMS-01 の状態 | タイマーを 59,999ms 進める（NY 現地は 09:30 を越えている） | `.value` は初回のまま（1 分未満では再判定しない。時計を直接読み直さず、間隔ごとの更新であることが分かる） | 実装済 |
| UMS-03 | UMS-01 の状態 | タイマーを 60,000ms 進める | `.value` がその時点の `getMarketStatus()` と同じ値に変わる（Pre-Market → Regular） | 実装済 |
| UMS-04 | 現在時刻を `2026-03-02T14:28:30Z` に固定してマウント | 60,000ms を 2 回進める | 各回の時点の `getMarketStatus()` と一致し続ける（1 回きりではなく間隔ごとに繰り返し更新される） | 実装済 |
