# utils/apiEnums（バックエンドの区分値）

- 略号: `AEN`
- 対象: `src/utils/apiEnums.js`
- テスト: `src/utils/apiEnums.spec.js`

`docs/api/openapi.json` の `components.schemas.*Enum` の写し。仕様の機械的な写しなので、
ラベルは持たない（表示名の出どころは `GET /codes` / `src/utils/*Types.js` / サーバが返す `*名`）。

export は 2 系統に分かれる。**spec に意味が書かれているかどうかで形が変わる。**

- 意味付きの凍結オブジェクト（7 種）… 参照元フィールドの description に意味がある
- `*_VALUES` の凍結配列（14 種）… 値だけが定義されていて、何を指すかの記載が無い

意味の分からない値にフロントが名前を付けると、それは仕様ではなく推測になる。形で分けておけば
参照側が推測を事実として扱えない。意味が spec に載ったら意味付きオブジェクトへ昇格させる。

**このファイルのテストだけは `openapi.json` を読み込んで突き合わせる。**
[utils-ca-types.md](utils-ca-types.md) が写しを手で持っているのは、コードが増えたときに
**表示名を付ける作業**が要るからで、そこは人が気づく必要がある。こちらは付けるものが無く、
写しを手で置くと「自分で書いた 2 つを比べる」だけになって仕様の変更を検知できない。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| AEN-01 | — | `openapi.json` の enum スキーマ名の集合と、対応表の集合を比べる | 過不足なく一致し、対応する export がすべて存在する（取り込み直しで区分が増減したらここが落ちる） | 実装済 |
| AEN-02 | — | 各 export の値を `openapi.json` の enum と比べる | 値も並び順も一致する | 実装済 |
| AEN-03 | — | 各 export に `Object.isFrozen()` をかける | すべて `true`（参照側が書き換えられない） | 実装済 |
| AEN-04 | — | 意味付きオブジェクトを数え、値の重複を見る | 7 種あり、いずれもキーと値が 1 対 1（同じ値に 2 つの名前が付いていない） | 実装済 |
| AEN-05 | — | 全 export の値の型を見る | すべて文字列（実 API の値はゼロ埋めされた文字列なので数値を混ぜない） | 実装済 |
