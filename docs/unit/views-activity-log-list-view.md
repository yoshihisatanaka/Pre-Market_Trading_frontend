# views/ActivityLogListView（操作ログ一覧画面）

- 略号: `ALV`
- 対象: `src/views/ActivityLogListView.vue`
- テスト: `src/views/ActivityLogListView.spec.js`

実際の Pinia ストア + vue-router（`createMemoryHistory`）+ MSW(node) を通して、**4 状態の出し分け**と
「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。
ヘッダへの Teleport は無いが、詳細ダイアログ（BaseModal）が body へ Teleport するので
`global: { stubs: { teleport: true } }` を付ける。
実ブラウザでの URL 同期は E2E が見る。こちらは過渡状態・手で書き換えられた URL クエリ・応答の差し替えを担保する。

検索条件と列の呼び名は画面モックに合わせてある。モックの「操作区分」（業務操作 / マスタ更新 / 運用管理）は
実 API の `区分`（2026-10-06 の回答 #38）。クエリには無いので、検索では `target_types` に展開して送る。
モックの「操作内容」が実 API の `操作区分`。

この画面に固有の、取り違えやすい点を 7 つ固定する。

- **URL のクエリ名は実 API のクエリ名にそろえてある**（`start_date` / `end_date` / `operator` / `actor_group` /
  `operation` / `target_types` / `target_key` / `sort`）。区分だけは実 API のクエリに無いので画面の言葉 `category`
- **操作内容・区分・実行者区分・並び順は URL の不正値を空に落とす。** 対象機能・操作者は選択肢が API 由来なので検査しない
- **対象機能の選択肢は API（`/operations/activity-logs/targets`）から来る。** 取得に失敗しても検索自体はでき、
  欄の下にエラー文言が出るだけ（ALV-15）
- **操作者の選択肢は `GET /masters/users`（無効な操作者も含む）から来る。** 取得失敗の扱いは対象機能と同じ（ALV-24）
- **区分は対象種別に展開してから送る。** 対象機能が選ばれていればそれが優先（ALV-20 / ALV-22）。
  区分を変えると対象機能の選択肢が絞られ、外れた選択は消える（ALV-21）。絞り込みは応答の 区分 を正とする（ALV-28）
- **区分のバッジは応答の 区分名 を優先し**、無い応答では対象種別から導いた区分の表示名（ALV-26 / ALV-27）
- **読むだけの画面。** 行の操作は「詳細」だけで、ダイアログで差分を見る

期待値はフィクスチャ（`src/mocks/fixtures/activityLogs.js` / `activityLogTargets.js` / `users.js`）と
`ACTIVITY_LOGS_PAGE_SIZE` から導く。実行者区分とロールの対応（営業員・IFA = sales / ifa、
管理者・管理責任者 = manager / supervisor）はモック（`src/mocks/handlers/activityLogs.js`）の読み方。
