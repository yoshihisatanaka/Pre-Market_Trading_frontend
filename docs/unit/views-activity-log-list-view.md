# views/ActivityLogListView（操作ログ一覧画面）

- 略号: `ALV`
- 対象: `src/views/ActivityLogListView.vue`
- テスト: `src/views/ActivityLogListView.spec.js`

実際の Pinia ストア + vue-router（`createMemoryHistory`）+ MSW(node) を通して、**4 状態の出し分け**と
「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。
ヘッダへの Teleport は無いが、詳細ダイアログ（BaseModal）が body へ Teleport するので
`global: { stubs: { teleport: true } }` を付ける。
実ブラウザでの URL 同期は E2E が見る。こちらは過渡状態・手で書き換えられた URL クエリ・応答の差し替えを担保する。

この画面に固有の、取り違えやすい点を 4 つ固定する。

- **URL のクエリ名は実 API のクエリ名にそろえてある**（`start_date` / `end_date` / `operator` / `operation` /
  `target_types` / `target_key` / `sort`）
- **操作区分と並び順は URL の不正値を空に落とす。** 対象種別は選択肢が API 由来なので検査しない
- **対象種別の選択肢は API（`/operations/activity-logs/targets`）から来る。** 取得に失敗しても検索自体はでき、
  欄の下にエラー文言が出るだけ（ALV-15）
- **読むだけの画面。** 行の操作は「詳細」だけで、ダイアログで差分を見る

期待値はフィクスチャ（`src/mocks/fixtures/activityLogs.js` / `activityLogTargets.js`）と
`ACTIVITY_LOGS_PAGE_SIZE` から導く。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| ALV-01 | 既定モック | マウント直後（応答前）を見る | ローディングが出て、表・空表示・エラー・件数は出ない。「検索」は押せない | 実装済 |
| ALV-02 | 既定モック | マウントして応答を待つ | 件数がフィクスチャの全件数で、表の行が `ACTIVITY_LOGS_PAGE_SIZE` 件。1 行目に先頭行の操作日時（整形済み）・対象種別名・操作区分名・操作者・対象キー・変更項目（`、` 区切り）が出る | 実装済 |
| ALV-03 | 既定モック | 表の列見出しを読む | `操作日時` / `対象種別` / `操作区分` / `操作者` / `対象キー` / `変更項目` / 操作列（空見出し）の 7 列がこの順に並ぶ | 実装済 |
| ALV-04 | 対象キーと操作者を持たない行（一括処理）がある | その行のセルを読む | 操作者と対象キーが `—` になる | 実装済 |

| ALV-12 | 7 種のクエリをすべて付けた URL でマウント | 応答を待つ | 条件が入力欄と並び順のボタンに反映され、その条件・その並びで絞り込まれた表が出る | 実装済 |
