# views/CorporateActionListView（CAマスタ一覧画面）

- 略号: `CAV`
- 対象: `src/views/CorporateActionListView.vue`
- テスト: `src/views/CorporateActionListView.spec.js`

実際の Pinia ストア + vue-router + MSW(node) を通して、
**4 状態の出し分け**と「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。

実ブラウザでの URL 同期は [docs/e2e/ca.md](../e2e/ca.md)（`CA`）が別に見る。
こちらは E2E では安定して観測できないもの（過渡状態・手で書き換えられた URL クエリ・
応答の差し替え）を担保する。分担は次のとおり。

| 論点 | E2E | 単体 | 理由 |
|---|---|---|---|
| ページ送り・検索の URL 同期 | CA-02 / 03 / 04 | CAV-11 / 12 | 実ブラウザの履歴まで見るのは E2E、条件の受け渡しは単体 |
| 未知の `ca_type` | — | CAV-14 | 画面の導線からは起こらない（手で URL を書いたときだけ） |
| `CA種別名` が欠けた応答 | — | CAV-06 | 応答の差し替えが要る。実 API は常に付けて返す |
| 表示件数の倍数でない `offset` | — | CAV-10 | 同上。画面の導線からは起こらない |

この画面は**一覧・新規追加・編集・削除**の CRUD 一式を持つ（CAV-16）。
同じ形の画面は [views-blackout-date-list-view.md](views-blackout-date-list-view.md)。

追加・編集の入力項目は `src/components/ca/CorporateActionFormFields.vue` に切り出してあり、
**その部品は単体テストを持たない**（`src/components/masters/` と同じ扱い）。
項目の並び・`maxlength`・必須の出しかたは、この文書が追加と編集の両方を通して担保する。

新規追加・編集・削除でも E2E と単体の分担がある。

| 論点 | E2E | 単体 | 理由 |
|---|---|---|---|
| 追加できること・成功の見えかた | CA-11 | CAV-17 | 実ブラウザで通ることは E2E、条件を保った読み直しは単体 |
| 入力の不備（必須・比率の片方だけ） | CA-13 | CAV-18 / 19 | 文言と出る位置は単体のほうが細かく見られる |
| 事前検証の不合格と通信障害の出し分け | CA-14 | CAV-20 / 21 | 応答の差し替えが要る |
| 登録・更新中はキャンセルもできない | — | CAV-22 / 30 | 過渡状態は E2E では安定して観測できない |
| 編集できること・現在値が入ること | CA-17 / 18 | CAV-25 / 26 | 同上 |
| 楽観的ロックの競合（409） | CA-21（見えかた） | CAV-29（出し先） | E2E は利用者に何が見えるか、単体はどの枠に出るか |
| 追加と編集でエラーの枠が混ざらないこと | — | CAV-31 | 片方のモーダルを開き直す操作が要り、E2E では回りくどい |
| 削除できること・確認の中身 | CA-23 / 24 | CAV-34 / 35 | 同上 |
| 削除中はキャンセルもできない | — | CAV-37 | 過渡状態は E2E では安定して観測できない |
| 最終ページの最後の 1 件を消すとページが戻る | CA-27 | CAV-38 | E2E は 6 件消す導線、単体は 1 件で同じ分岐に入れる |

**画面で弾かないもの**（サーバの事前検証に委ねる。意図的な非検査）:

- **日付 3 種の前後関係**（権利付最終日 ≤ 効力発生日 ≤ 支払日）。openapi が宣言しているのは
  「日付妥当性検証」だけで順序は書かれておらず、`POST /masters/ca/import-csv` で取込まれた
  順序の変な行を画面から直せなくなる（備考の誤記すら直せない）
- **銘柄コードが銘柄マスタに実在するか。** サーバだけが判断できる（CAV-20 でその出しかたを見る）
