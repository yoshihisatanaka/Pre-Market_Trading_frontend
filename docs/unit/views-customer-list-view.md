# views/CustomerListView（顧客マスタ一覧画面）

- 略号: `CLV`
- 対象: `src/views/CustomerListView.vue`
- テスト: `src/views/CustomerListView.spec.js`

実際の Pinia ストア + vue-router + MSW(node) を通して、
**4 状態の出し分け**と「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。

実ブラウザでの URL 同期は E2E（`docs/e2e/customers.md`）が別に見る。こちらは E2E では安定して
観測できないもの（過渡状態・手で書き換えられた URL クエリ・応答の差し替え・
コードマスタが未取得の瞬間）を担保する。

この画面に固有の、取り違えやすい点を 4 つ固定する。

- **プルダウンの選択肢はコードマスタ由来。** この画面は `load` を呼ばない（`main.js` が起動時に
  1 回だけ読む）ので、コードマスタが未取得のままでも検索カードは描けなければならない（CLV-19）
- **`米国株評価額` / `評価損益` の列は無い。** 画面モックにはあるが、2026-09-28 に不要と決まり
  列ごと削除した（CLV-04）。右端は見出しの無い操作列
- **金額は単位を後置する**（`3,500,000 円` / `50,000.00 ドル`）。
  残高 0 は `0 円` で、`null`（値が無い）だけが `—`（CLV-07）
- **バッジは 2 種類ある。** 取引停止は取引規制の列、事故処理口座は口座区分の列に**併記**する
  （区分名を置き換えない）

**新規追加と編集はあるが、削除は無い**（2026-09-28 決定。CLV-21）。ヘッダの `customers-add` と
行の `customers-edit-{id}` から `MasterFormDialog`（`size="lg"`）を開き、入力欄は
`CustomerFormFields` が `src/utils/customerFields.js` の項目表から組み立てる
（testid は `customers-add-{項目の testid}` / `customers-edit-{項目の testid}`）。
入力の検査規則そのものは [utils-customer-fields.md](utils-customer-fields.md) が見るので、
ここでは「項目の直下に出る」「API へ送らない」という画面の振る舞いだけを見る。

登録は「サーバの事前検証 → 登録」の 2 段で、**事前検証の警告（取消済みの口座番号の再有効化）が出たら
1 回目は登録せず警告を出し、押し直すと登録する**（CLV-27）。楽観的ロックの 409 は
事前検証ではなく通信・サーバ障害の枠（`customers-edit-error`）に出す（CLV-30）。

期待値はフィクスチャ（`src/mocks/fixtures/customers.js` / `codes.js`）と
`CUSTOMERS_PAGE_SIZE` / `CUSTOMER_FIELDS` から導く。新しい口座番号はフィクスチャの全口座番号
（取消済みを含む）の最大値 + 1。
