# views/ExecutionListView（約定照会画面）

- 略号: `EXV`
- 対象: `src/views/ExecutionListView.vue`
- テスト: `src/views/ExecutionListView.spec.js`

実際の Pinia ストア + vue-router（`createMemoryHistory`）+ MSW(node) を通して、**4 状態の出し分け**と
「ページ位置・検索条件は URL クエリが正」の単方向フロー、件数カードの出し分けを守る。
`global: { stubs: { teleport: true } }` を付ける。
実ブラウザでの URL 同期は E2E が見る。こちらは E2E では安定して観測できないもの（過渡状態・手で書き換えられた
URL クエリ・応答の差し替え）を担保する。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| EXV-01 | 応答を握ったまま | マウントする | ローディングが表示され、表と空表示とエラーは出ない。件数カードの値はすべて「—」 | 実装済 |
| EXV-02 | `GET /executions` が 500 | マウントする | エラーの理由と「再試行」が表示され、表は出ない。件数カードの値はすべて「—」 | 実装済 |
| EXV-03 | 0 件の応答 | マウントする | 「該当する約定はありません。」が表示され、表は出ない。総約定件数は「0」 | 実装済 |
| EXV-04 | 既定モック | マウントする | 件数と 1 ページぶんの行が表示され、1 行目が約定日時の最も新しいフィクスチャ行の値になる（期待値はフィクスチャから導く） | 実装済 |
| EXV-05 | EXV-02 の状態 | 「再試行」を押す（応答は既定に戻す） | 一覧が表示される | 実装済 |

| EXV-08 | `?side=x&status=999&route=9`（選択肢に無い値） | マウントする | 3 つとも条件なしとして扱われ（リクエストに載らない）、プルダウンは「-- 全て --」の表示になる | 実装済 |

| EXV-12 | 売買区分が買 / 売 / 未知の行 | マウントする | 売買が「買」/「売」/「—」になる | 実装済 |
| EXV-13 | 既定モック | マウントする | 件数カードが 総約定件数 / 買い約定 / 売り約定 に `summary` の値を出し、一部出来は「—」のまま | 実装済 |
| EXV-14 | 既定モック | マウントする | 約定単価が小数第 4 位までの「ドル」表記（`227.1600 ドル`）、約定代金が小数第 2 位までの「ドル」表記（`2,276.55 ドル`）、約定日時が `MM/DD HH:mm` で出る | 実装済 |
