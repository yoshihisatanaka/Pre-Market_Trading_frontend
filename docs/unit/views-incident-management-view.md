# views/IncidentManagementView（障害管理画面）

- 略号: `INV`
- 対象: `src/views/IncidentManagementView.vue`
- テスト: `src/views/IncidentManagementView.spec.js`（未作成）
- E2E 側のシナリオ: [docs/e2e/incidents.md](../e2e/incidents.md)

ヘッダへ `Teleport` するため、テストには `global: { stubs: { teleport: true } }` を付ける。

**4 状態のチェーンは 1 本。** 運用状態と障害対応履歴はストアが 1 回の取得にまとめているので、
ローディング / エラー / 空 / データあり は画面全体に対して 1 本引く。
**履歴 0 件はこの「空」ではない**（データあり側の内訳で、制御ボタンは表示されたまま）。
画面の「空」は運用状態そのものが取れなかったときに限る。

運用状態の文言はサーバが返す `operationStateName` をそのまま出す。「IB送信だけ制御中を何と呼ぶか」は
業務判断なので画面では合成しない。画面が決めるのは**色だけ**で、判定にはコード（`operationState`）を使う。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| INV-01 | 取得が終わっていない | 画面をマウントする | 回転マークが表示され、制御ボタンも履歴も表示されない | 未着手 |
| INV-02 | 取得が 500 を返す | 画面をマウントする | エラーメッセージと「再試行」ボタンが表示され、制御ボタンも履歴も表示されない | 未着手 |
| INV-03 | INV-02 の状態から取得が回復する | 「再試行」を click | エラーメッセージが消え、現在の運用状態と制御 2 区画が表示される | 未着手 |
| INV-04 | 運用状態が取得できない（本文なし） | 画面をマウントする | 「現在の運用状態を取得できませんでした。」が表示される | 未着手 |
| INV-05 | 既定モック（通常運用・履歴 3 件） | 画面をマウントする | 「通常運用」と、「IB送信制御」「注文入力制御」の 2 区画が表示される | 未着手 |
| INV-06 | 既定モック | 画面をマウントする | 説明文「障害発生時のIB送信制御と注文入力制御を分けて管理します。」が取得の成否によらず表示される | 未着手 |
| INV-07 | 運用状態は取れるが履歴が 0 件 | 画面をマウントする | 履歴の表は表示されず「現段階では制御ボタンの表示のみです。…」が出る。制御ボタンは表示されたまま、空状態の文言は出ない | 未着手 |
| INV-08 | 運用状態が「停止中」 | 画面をマウントする | 「停止中」が表示され、通常運用のときとは別の（危険色の）見た目になる | 未着手 |
| INV-09 | 既定モック | 「IB送信を制御」を click | 確認ダイアログが開き、IB送信制御の文言が表示される | 未着手 |
| INV-10 | 既定モック | 「注文入力を制御」を click | 確認ダイアログが開き、注文入力制御の文言が表示される | 未着手 |
| INV-11 | INV-09 の状態 | ダイアログが close を emit する | ダイアログが閉じ、現在の運用状態は変わらない | 未着手 |
| INV-12 | 既定モック | ヘッダの「再読み込み」を click | 取得がやり直される（再取得後も現在の運用状態が表示される） | 未着手 |
| INV-13 | 履歴が 3 件ある | 画面をマウントする | 表の列見出しが 変更日時 / 変更前 / 変更後 / 障害対応の内容 / 更新者 の順で並び、3 行表示される | 未着手 |
