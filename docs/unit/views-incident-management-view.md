# views/IncidentManagementView（障害管理画面）

- 略号: `INV`
- 対象: `src/views/IncidentManagementView.vue`
- テスト: `src/views/IncidentManagementView.spec.js`
- E2E 側のシナリオ: [docs/e2e/incidents.md](../e2e/incidents.md)

停止・再開のダイアログ（`BaseModal` の `Teleport to="body"`）を wrapper 内に描くため、
テストには `global: { stubs: { teleport: true } }` を付ける。

**4 状態のチェーンは 1 本。** 停止状態と操作履歴はストアが 1 回の取得にまとめているので、
ローディング / エラー / 空 / データあり は画面全体に対して 1 本引く。
**履歴 0 件はこの「空」ではない**（データあり側の内訳で、停止対象のカードは表示されたまま）。
画面の「空」は停止状態そのものが取れなかったときに限る。

「現在の運用状態」の文言は `src/utils/suspensionState.js` の `summarizeSuspension()` が組み立てる
（サーバはフラグしか返さない）。合成規則そのものの網羅はそちらの単体テストで持ち、ここでは画面に出ることだけを見る。

**停止対象はモック `08986d1`（2026-09-24）と同じカードで並べる**（1 対象 = 1 枚・2 列）。1 枚に
停止対象名・説明文・スライド式トグル（`BaseSwitch`・ON = 停止中）・状態（通常 / 停止中）を載せる。
トグルは押すと確認ダイアログが開くだけ（確定までトグルは切り替わらない）。
**応答の停止理由・停止日時・停止者・再開日時・再開者はカードに出さない**（理由は履歴の停止理由列で見る）。
履歴は 変更日時 / 制御内容 / 停止理由 / 更新者 の 4 列。変更日時は年なし（`MM/DD HH:mm`）、更新者はコードの下に氏名
（氏名は契約提案の `操作者名`。無ければコードだけ）。
「現在の運用状態」の枠はモックと同じく見出し行（説明文の右）に置き、取得の成否によらず出す（取得前・失敗時は「—」）。
トグル単体の振る舞いは [components-ui-base-switch.md](components-ui-base-switch.md) が持つ。
