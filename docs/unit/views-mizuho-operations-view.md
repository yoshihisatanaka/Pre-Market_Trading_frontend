# views/MizuhoOperationsView（みずほ注文締）

- 略号: `MZV`
- 対象: `src/views/MizuhoOperationsView.vue`
- テスト: `src/views/MizuhoOperationsView.spec.js`
- E2E 側のシナリオ: [docs/e2e/mizuho-operations.md](../e2e/mizuho-operations.md)

実際の Pinia ストア + vue-router（`createMemoryHistory`）+ MSW(node) を通して、締めカードと約定一覧の
**4 状態をそれぞれ出し分ける**ことと、「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。
`global: { stubs: { teleport: true } }` を付ける。実ブラウザでの URL 同期は E2E が見る。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| MZV-01 | 両方の応答を握ったまま | マウントする | 締めカードと一覧の両方にローディングが出て、表・空表示・エラーは出ない。件数カードはすべて `—` | 実装済 |
| MZV-02 | `GET /executions` が 500 | マウントする | 一覧にエラーの理由と「再試行」が出て、締めカードは「受付中」のまま出る | 実装済 |
| MZV-03 | `GET /closing/status` が 500 | マウントする | 締めカードにエラーの理由と「再試行」が出て、一覧は 12 件のまま出る | 実装済 |
| MZV-04 | `GET /closing/status` の本文が空 | マウントする | 締めカードに「みずほ注文の締め状態を取得できませんでした。」が出る | 実装済 |
| MZV-05 | 0 件の応答 | マウントする | 「該当する約定はありません。」が表示され、表は出ない | 実装済 |
| MZV-06 | 既定モック | マウントする | 件数 12 件と 12 行が表示され、1 行目がフィクスチャ先頭行（`#1`・MSFT）の値になる | 実装済 |
| MZV-07 | MZV-02 の状態 | 一覧の「再試行」を押す（応答は既定に戻す） | 一覧が表示される | 実装済 |
| MZV-08 | 既定モック | 売買区分に「売り」を選んで「検索」 | ルートのクエリが `side=1` になり、その条件で再取得される | 実装済 |
| MZV-09 | `?status=unknown`（未知の区分） | マウントする | 落ちずに条件なしの 12 件として表示される（api 層が `status` を送らない） | 実装済 |
| MZV-10 | 既定モック（受付中） | 「みずほ注文締め」を押す | 確認ダイアログが開き、主ボタン「締める」は押せない。「キャンセル」で閉じる | 実装済 |
| MZV-11 | 締め済の応答 | 「注文ファイル作成」を押す | 注文ファイル作成の確認ダイアログが開き、主ボタン「作成する」は押せない | 実装済 |
