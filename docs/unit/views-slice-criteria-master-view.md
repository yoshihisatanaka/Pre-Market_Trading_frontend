# views/SliceCriteriaMasterView（スライス基準マスタ画面）

- 略号: `SCV`
- 対象: `src/views/SliceCriteriaMasterView.vue`
- テスト: `src/views/SliceCriteriaMasterView.spec.js`
- E2E 側のシナリオ: [docs/e2e/slice-criteria.md](../e2e/slice-criteria.md)

ストアが持つ比率（`0.05`）と画面の表記（`5.00%`）の変換、および入力欄の初期化はこの画面の責務。
ヘッダへ `Teleport` するため、テストには `global: { stubs: { teleport: true } }` を付ける。

入力値の検証は画面では行わず、実 API（422）が返す理由をそのまま出す。実 API の `msg` は
項目名を含まないので、`src/api/client.js` が `loc` から項目名を補って
「市場関与率: 指定できる下限を下回っています」の形にする。

更新できるのは管理責任者だけ、という出し分けもこの画面が持つ。ログインユーザとロールの仕組みが
まだ無いため、画面モックの `?as_user` に倣って **URL クエリ `?as_user=viewer` のときだけ閲覧のみ**
にする仮実装で、既定（クエリなし）は編集可。仕組みが入ったらこの判定だけ差し替える。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| SCV-01 | 取得が終わっていない | 画面をマウントする | 回転マークが表示され、現在値も設定変更フォームも表示されない | 実装済 |
| SCV-02 | 取得が 500 を返す | 画面をマウントする | エラーメッセージと「再試行」ボタンが表示され、設定変更フォームは表示されない | 実装済 |
| SCV-03 | 取得が本文なしを返す（実 API では起きないが、4 状態を保つための防御） | 画面をマウントする | 「スライス基準が設定されていません。」が表示される | 実装済 |
| SCV-04 | 既定モック | 画面をマウントする | `5.00%` / `10,000 株` / `USD 1,000,000` が表示される | 実装済 |
| SCV-05 | 既定モック | 画面をマウントする | 入力欄の初期値が 市場関与率 `5`、数量 `10000`、金額 `1000000` になる | 実装済 |
| SCV-06 | 既定モック | 市場関与率に `3` を入れて保存する | 「スライス基準を保存しました。」が表示され、現在値の市場関与率が `3.00%` に変わる | 実装済 |
| SCV-07 | 既定モック | 市場関与率に `0` を入れて保存する | 保存できない理由が表示され、成功メッセージは表示されない。現在値は `5.00%` のまま | 実装済 |
| SCV-08 | 取得が 500 を返した後 | 「再試行」ボタンを押す（2 回目は成功する） | エラー表示が消え、現在値が表示される | 実装済 |
| SCV-09 | 既定モック、クエリなし | 画面をマウントする | 「管理責任者」が表示され、設定変更フォームが出る（閲覧のみの案内は出ない） | 実装済 |
| SCV-10 | 既定モック、`?as_user=viewer` で開く | 画面をマウントする | 「閲覧のみ」と「更新は管理責任者だけが実行できます。」が表示され、設定変更フォームは出ない。現在値は読める | 実装済 |
