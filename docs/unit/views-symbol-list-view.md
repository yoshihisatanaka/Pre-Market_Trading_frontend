# views/StockListView（銘柄マスタ一覧画面）

- 略号: `STV`
- 対象: `src/views/StockListView.vue`
- テスト: `src/views/StockListView.spec.js`

実際の Pinia ストア + vue-router + MSW(node) を通して、
**4 状態の出し分け**と「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。

実ブラウザでの URL 同期は銘柄マスタの E2E シナリオ（`docs/e2e/` 配下・別途）が見る。
こちらは E2E では安定して観測できないもの（過渡状態・手で書き換えられた URL クエリ・
応答の差し替え）を担保する。分担は次のとおり。

| 論点 | E2E | 単体 | 理由 |
|---|---|---|---|
| ページ送り・検索の URL 同期 | E2E 側で見る | STV-12 / 13 / 14 | 実ブラウザの履歴まで見るのは E2E、条件の受け渡しは単体 |
| 未知の `regulation` | — | STV-15 | 画面の導線からは起こらない（手で URL を書いたときだけ） |
| 区分名が欠けた応答 | — | STV-07 | 応答の差し替えが要る。実 API は常に付けて返す |
| 表示件数の倍数でない `offset` | — | STV-11 | 同上。画面の導線からは起こらない |
| 相場が未取得（`null`）の行 | — | STV-05 | フィクスチャ依存の行を狙い撃つ |

検証するのは**表示名**であって、取引可否セルの色ではない。`規制情報` のコード値は
仮置き（[utils-stock-types.md](utils-stock-types.md)）で、差し替わると色の条件も変わるため。

この画面は**読むだけ**で、新規追加・編集・削除の導線を持たない（STV-17）。
持つ画面の例は [views-blackout-date-list-view.md](views-blackout-date-list-view.md)。

期待値はフィクスチャ（`src/mocks/fixtures/stocks.js`）・`STOCKS_PAGE_SIZE`・
`src/utils/format.js` の整形関数から導く。

| ID | 前提 | 操作 | 期待結果 | 状態 |
|---|---|---|---|---|
| STV-01 | 既定モック | マウント直後（応答前）を見る | 回転マークが出て、表も空状態も出ない | 実装済 |
| STV-02 | 既定モック | マウントして応答を待つ | 件数がフィクスチャの全件数で、表の行が `STOCKS_PAGE_SIZE` 件。1 行目の銘柄コード・ティッカーコード・銘柄名（英語・日本語）がフィクスチャの先頭行と一致する | 実装済 |
| STV-03 | 既定モック | 表の列見出しを読む | `銘柄コード` / `ティッカーコード` / `銘柄名（英語）` / `銘柄名（日本語）` / `前日終値` / `前日出来高` / `5日平均出来高` / `取引可否` / `預託先区分` / `VWAP対象区分` / `備考` の 11 列がこの順に並ぶ。操作列は無い | 実装済 |
| STV-04 | 既定モック（ユーザー操作フラグ 1 と 0 の行を含む） | マウントして応答を待つ | フラグ 1 の行にだけ `is-user-modified` が付き、0 の行には付かない | 実装済 |
| STV-05 | 相場の 3 項目が未取得（`null`）の行がある | マウントして応答を待つ | その行の前日終値・前日出来高・5日平均出来高がいずれも `—` になる（空欄にしない） | 実装済 |
| STV-06 | 既定モック | 1 行目の相場のセルを読む | 前日終値が `227.16 ドル` の形（通貨記号を使わない）、出来高 2 列が 3 桁区切りの整数で出る | 実装済 |
| STV-07 | API が区分名（`規制情報名` / `注文ルート名` / `VWAP対象区分名`）を持たない行を返す | マウントして応答を待つ | 3 つのセルにコードから引いた表示名が出る（コードの数字をそのまま出さない） | 実装済 |
| STV-08 | API が 0 件を返す | マウントして応答を待つ | 「該当する銘柄はありません。」が出て、表は描画されない | 実装済 |
| STV-09 | API が 500 を返す | マウントして応答を待つ | エラーの理由と「再試行」ボタンが出て、表も空状態も出ない | 実装済 |
| STV-10 | API が 500 を返した後、正常応答に戻る | 「再試行」を click | 表が描画され、エラー表示が消える | 実装済 |
| STV-11 | 既定モック。`?offset=7`（表示件数の倍数でない） | マウントして応答を待つ | 丸めずその位置から `STOCKS_PAGE_SIZE` 件が出る | 実装済 |
| STV-12 | 既定モック | ページ送りの「2」を click | URL に `offset` が乗り、表が 2 ページ目に入れ替わる | 実装済 |

| STV-14 | 既定モック。絞り込み済み | 「クリア」を click | URL クエリが空になり、全件に戻る | 実装済 |
| STV-15 | `?regulation=9`（実在しないコード） | マウントして応答を待つ | 条件なしとして捨てられ、全件が出る。セレクトは「-- すべて --」のまま | 実装済 |
| STV-16 | API が 0 件 / 500 / 正常 のいずれか | マウントして応答を待つ | 説明バナーと検索カードはどの状態でも消えない（0 件やエラーのときこそ条件を直したい） | 実装済 |
| STV-17 | 既定モック | ヘッダと表の操作を見る | ヘッダに「再読み込み」だけがあり「新規追加」は無い。行にも編集・削除のボタンが無い | 実装済 |
