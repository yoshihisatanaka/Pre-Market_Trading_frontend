# views/UserListView（ユーザ管理マスタ一覧画面）

- 略号: `USV`
- 対象: `src/views/UserListView.vue`
- テスト: `src/views/UserListView.spec.js`

実際の Pinia ストア + vue-router（`createMemoryHistory`）+ MSW(node) を通して、**4 状態の出し分け**と
「ページ位置・検索条件は URL クエリが正」の単方向フローを守る。`global: { stubs: { teleport: true } }` を付ける
（この画面は Teleport を使わないが、編集モーダルの `BaseModal` が body へ Teleport する）。
実ブラウザでの URL 同期は E2E が見る。こちらは E2E では安定して観測できないもの（過渡状態・手で書き換えられた
URL クエリ・応答の差し替え・送った本文）を担保する。

この画面に固有の、取り違えやすい点を 4 つ固定する。

- **状態の既定は「すべて」**（無効な利用者も出る）。URL の `status` は `active` だけを解釈し、
  それ以外は「すべて」に寄せる（USV-12）
- **所属部店名は部店の選択肢（コードマスタ）から引く。** `OperatorItem` に部店名が無い（docs/api/requests.md #67）。
  この画面はコードマスタを読み込まない（`main.js` が起動時に読む）ので、未取得でも壊れない（USV-09）
- **編集で変えられるのはロールと状態だけ。** 社員コード・氏名・所属部店は読み取り専用で、
  更新の本文には**画面に出さない受注者コードも今の値で送り返す**（省くと null で上書きされる。USV-17）
- **ロールの選択肢（権限マスタ）の失敗は一覧を止めない。** 帯で知らせて再読み込みでき、
  編集では今のロールが選択肢から消えない（USV-21〜USV-23）

新規追加・削除は画面モックに無いので持たない（USV-24）。
